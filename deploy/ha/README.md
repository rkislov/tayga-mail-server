# Примеры для кластера Tayga

Используются с [инструкцией](../../docs/ha.md). Адреса, WWID, имена узлов и сертификат заменяются на реальные. Примеры проверяются статически и загрузчиком настроек Tayga; испытания Pacemaker/СХД обязательны.

- `tayga-ha.service` — единственный кластерный экземпляр; не включать через `systemctl enable`.
- `wait-ready.sh` — проверка HTTPS и БД при запуске. Постоянный контроль выполняет внешний мониторинг.
- `tayga-sqlite.yaml` — каркас нового тестового экземпляра. При переносе сохранять действующие настройки.
- `tayga-postgres.yaml` — новый экземпляр с PostgreSQL через UNIX-сокет и peer-аутентификацию.
- `drbd-tayga.res.example` — репликация тома вместо MetroLUN, после замены параметров.

Бинарник `/opt/tayga/0.9.30/tayga-mail` одинаков на обоих узлах. Том монтируется в `/var/lib/tayga`; маркер `.ha-volume-id` содержит `tayga-prod-01`. Идентификатор изменять одновременно в маркере и unit-файле.

Боевых паролей в шаблонах нет. YAML не подставляет переменные окружения. Настройки из БД могут перекрывать YAML, включая пути сертификатов и режим HA.
