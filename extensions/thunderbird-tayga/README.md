# Tayga Mail 2.2.0 — Thunderbird + EWS

Автоматическая двусторонняя синхронизация почты, календарей, задач и контактов Tayga в **Thunderbird 145+**. Проверено в Thunderbird **150.0.2** на macOS с настоящим серверным обработчиком FlowSync и отдельным временным профилем.

Пакет: `dist/tayga-thunderbird-v2.2.0.xpi` в корне репозитория. Для двусторонней синхронизации календарей и контактов требуется **сервер Tayga из этой версии исходников**: плагин проверяет возможность полного обмена перед записью. Со старым сервером локальная очередь сохраняется, а интерфейс предлагает обновить сервер.

## Подключение

1. Соберите XPI: `npm run build` в этой папке.
2. Thunderbird → Дополнения и темы → шестерёнка → **Установить дополнение из файла** → выберите XPI. Для разработки можно загрузить `manifest.json` через отладку дополнений.
3. Откройте настройки Tayga Mail, введите HTTPS-адрес сервера, почту и пароль. При MFA введите TOTP или резервный код.
4. Плагин создаёт почтовую учётную запись EWS, календари, список задач и адресные книги Tayga. Проверка изменений выполняется автоматически при входе, при запуске Thunderbird и раз в минуту. Кнопка **Синхронизировать сейчас** запускает обмен вручную.

Для доступа к нативному EWS-аккаунту и локальному календарному хранилищу используется Thunderbird Experiment API. Поэтому при установке Thunderbird запрашивает полный доступ расширения. Сборка не подписана и не опубликована в каталоге дополнений.

Почтовые данные, события и карточки передаются через `/EWS/Exchange.asmx`. Вход и обновление токена используют `/api/v1/auth/login`, `/api/v1/auth/mfa/verify`, `/api/v1/auth/token`. Пароль не сохраняется. Для EWS-запросов управляемого почтового аккаунта используется Bearer-токен сессии; отдельного ввода пароля для IMAP/SMTP/DAV не требуется.

## Синхронизация

**Почта:** используется встроенный EWS-движок Thunderbird. Плагин настраивает входящий и исходящий EWS-серверы, идентификатор отправителя и автоматическую проверку почты. Сквозная проверка охватывает получение письма, передачу статуса «прочитано», отправку письма с вложением и сохранение копии в Sent. Остальные почтовые операции зависят от поддержки соответствующей команды FlowSync и версией Thunderbird.

**Календари:** обнаружение серверных коллекций, перенос полных iCalendar-ресурсов, локальное создание, изменение и удаление событий. Сохраняются повторения, исключения, часовые пояса, участники, напоминания и дополнительные поля, которые передаёт iCalendar. Локальные изменения направляются в общий серверный путь календарных правок и планирования встреч. Отправка приглашений отдельно через SMTP со стороны локального календаря отключена, чтобы не дублировать серверную обработку.

**Задачи (2.2.0):** отдельный список «Tayga · Tasks» (название зависит от серверной папки), двустороннее создание, изменение и удаление. Передаются название, описание, начало и срок, прогресс, завершение и повторное открытие, приоритет, категории и локальные напоминания. Серверные состояния «ожидание»/«отложено» и дробный процент сохраняются при обмене с Thunderbird. Обновления из веба, EWS и ActiveSync отражаются в общей модели задачи. Повторяющиеся и делегируемые VTODO не отправляются: плагин сохраняет локальную запись и показывает ошибку.

При обновлении с 2.1 локальные задачи, ошибочно созданные в управляемых календарях событий, переносятся в список задач. Исходная запись удаляется только после сохранения копии и очереди; в `tayga-ews-state.json` остаётся снимок восстановления. Чужие календари и задачи с серверным идентификатором не переносятся. Сначала обновите сервер: он должен возвращать `TaygaTasksVersion=1`; без этой возможности обмен задачами приостановлен.

**Контакты:** обнаружение адресных книг и двусторонний обмен полными vCard-ресурсами. Сохраняются дополнительные адреса, телефоны, заметки и поля карточки. Корпоративный GAL и служебные коллекции Exchange не превращаются в редактируемые личные адресные книги.

Создание и переименование календарных коллекций и адресных книг выполняется в Tayga. Локальные зеркала создаются плагином. Это интеграция с Tayga; полный обмен календарей/контактов использует согласованные именованные EWS-свойства и не заявлен для произвольного Microsoft Exchange.

## Очередь, конфликты и восстановление

- Локальные данные находятся в штатных хранилищах Thunderbird. Очередь правок и связь с серверными объектами атомарно сохраняются в `tayga-ews-state.json` профиля, с резервной копией; курсоры EWS — в локальном хранилище расширения.
- Перед отправкой учитывается версия объекта. При конфликте локальная правка сохраняется и не перезаписывается серверной копией. В настройках можно выбрать **Сохранить локальную версию** или **Взять серверную версию**.
- Создание использует постоянный идентификатор операции. Повтор после потери ответа не создаёт второй объект. Более новая локальная правка, появившаяся во время отправки предыдущей, остаётся в очереди.
- После запуска выполняется сверка локальных хранилищ: правки, сделанные без активного обработчика расширения, тоже попадают в очередь.
- Недействительный курсор вызывает полную пересинхронизацию, включая удалённые серверные объекты. Курсор страницы сохраняется после применения данных.
- При удалении коллекции на сервере её локальные данные не удаляются автоматически. Неотправленные правки отмечаются как конфликт.
- Выход и отключение синхронизации сохраняют локальные данные. Активно синхронизируется одна сессия Tayga. При переключении пользователя прежние данные и его очередь остаются в профиле, но отправляется очередь только текущего пользователя.
- Ограничение полного ресурса календаря или контакта на сервере — 2 МиБ. Ограничения вложений почты определяются сервером и Thunderbird. Бинарные вложения событий не загружаются этим календарным мостом; используйте серверные ссылки в событиях.

Адрес сервера должен содержать только HTTPS origin, без пути, параметров или встроенных учётных данных. Для разработки разрешён HTTP на `localhost`, `127.0.0.1`, `[::1]`. Изменения существующих учётных записей, не созданных этим плагином, не выполняются.

## Дополнительные сервисы

Сохраняются возможности companion-плагина:

- **Filelink:** загрузка больших вложений в Tayga Files, вставка ссылки средствами Thunderbird, отмена загрузки, удаление Filelink-файла и отзыв общей ссылки. Провайдер добавляется в настройках Thunderbird → Составление → Вложения → Tayga Mail.
- Настраиваемый срок ссылки: 1–8760 часов, по умолчанию 7 дней. Любой обладатель ссылки может скачать файл до истечения или отзыва. Файлы размещаются в `tb-out/{uuid}/{filename}` и занимают квоту пользователя. При сбое плагин пытается убрать неполную загрузку; при разрыве связи оставшиеся файлы можно проверить в Tayga Files.
- **Sieve:** список, редактор, сохранение, активация и удаление скрипта. На сервере активен один скрипт.
- **Автоответчик:** просмотр, изменение и отключение. Его включение заменяет активный Sieve-фильтр; после отключения нужный фильтр можно активировать снова.
- Темы Tayga/Cosmos и быстрый переход в веб-интерфейс.

Нет телеметрии. Сессионные токены хранятся в локальном профиле расширения, поэтому профиль должен быть защищён средствами ОС. Выход удаляет локальные токены; серверные сессии отзываются в Tayga. WebAuthn/OIDC-вход в расширении пока не реализован.

## Сборка и проверки

Node.js 22+, Python 3, для серверных тестов — Go из `go.mod`.

```bash
cd extensions/thunderbird-tayga
npm test
npm run build
npm run test:thunderbird
```

`test:thunderbird` проверяет интерфейс и companion-функции с локальным тестовым REST API, без синхронизации EWS. Для полной проверки **реального Thunderbird с реальным FlowSync** из корня репозитория:

```bash
TAYGA_THUNDERBIRD_E2E=1 go test ./internal/flowsync -run TestTaygaEWSThunderbirdNative -v -count=1
```

Проверка создаёт отдельные временные БД, Maildir и профиль Thunderbird, не использует рабочие аккаунты и не отправляет внешнюю почту. Она проверяет EWS-аккаунт, оба направления календарного/контактного обмена и задач, восстановление ошибочной очереди 2.1, завершение и повторное открытие задач, потерю ответа создания с последующим локальным изменением, конфликтные версии, повторы, сброс курсоров, восстановление локальных правок и перезапуск Thunderbird с неотправленной очередью. Для другого расположения приложения задайте `THUNDERBIRD_BINARY=/path/to/thunderbird`.

```bash
go test ./internal/flowsync ./internal/storage
# Из папки расширения:
node --check ews.js
node --check experiments/ews/api.js
```

Стандартный `web-ext lint` ориентирован на Firefox: он сообщает о Thunderbird API и отклоняет `experiment_apis` по правилам привилегированных Firefox-расширений. Этот результат не заменяет проверку в Thunderbird, где Experiment API разрешён обычным дополнениям. XPI содержит только файлы из явного списка `package.py`; тестовые привилегированные команды, документация и локальные настройки в пакет не включаются.

## Контракт полного обмена Tayga EWS

Именованные свойства имеют `PropertySetId=f3db8cb0-04eb-49ca-bd89-720f85e98dd7`, `PropertyType=String`:

- `TaygaSyncVersion`: `GetFolder` с запросом этого свойства возвращает `1`.
- `TaygaTasksVersion`: `GetFolder` возвращает `1` при поддержке VTODO.
- `TaygaVTodo`: полный VCALENDAR с одним VTODO в EWS Task; чтение только по явному запросу свойства. Создание использует атомарную квитанцию в БД, `task-create:<UUID>` позволяет восстановить результат после потери ответа. Удаление проверяет ревизию в одной транзакции.
- `TaygaICalendar` / `TaygaVCard`: полный ресурс в `GetItem`, `CreateItem`, `UpdateItem`.
- `TaygaCreateId`: постоянный UUID создаваемого объекта, обеспечивающий повтор создания после потери ответа.
- `TaygaDelete=true`: условное удаление через `UpdateItem` с текущим `ItemId/ChangeKey`.

Изменение требует актуальный `ChangeKey`; CalendarObject сохраняется через `SaveCalendarClientObject` с атомарной ETag-проверкой. vCard сохраняется и удаляется с условием по ETag в SQL-транзакции. Обычные EWS-клиенты получают стандартные поля; полные ресурсы выдаются только при запросе соответствующего именованного свойства.

Официальная документация: [EWS в Thunderbird](https://wiki.mozilla.org/Thunderbird:Exchange), [Experiment API](https://developer.thunderbird.net/add-ons/mailextensions/experiments), [Filelink](https://webextension-api.thunderbird.net/en/mv2/cloudFile.html).

## Правила почты (2.1.0)

Откройте «Tayga Mail → Правила почты» в панели плагина или кнопку «Открыть редактор правил» в настройках. Слева — включение и порядок правил; справа — название, условия, действия и исключения. Изменения применяются кнопкой «Сохранить на сервере». Удаление из списка до сохранения можно отменить повторной загрузкой.

Правила используют GetInboxRules/UpdateInboxRules и выполняются на сервере для новых входящих писем, в том числе при закрытом Thunderbird. Они совместимы с поддерживаемыми Tayga правилами Outlook и выполняются перед личным Sieve-скриптом. Обработка уже полученной почты не запускается.

Поддерживаются тема и текст, адреса отправителя и получателей, «мне»/«копия мне», несколько значений, исключения, перемещение и копирование в папки, удаление, отметка прочитанным и остановка обработки. Условия объединяются через «и», значения — через «или», исключения — через «или». Без условий правило применяется ко всем новым письмам. Пересылка, категории и важность пока не поддерживаются сервером и не предлагаются редактором. Правила с неизвестными полями показываются без возможности редактировать их содержимое.

Перед сохранением редактор повторно читает правила и отклоняет сохранение при изменениях из другого клиента; черновик остаётся в открытой вкладке. После сетевой ошибки обновите список для проверки состояния сервера. Это предварительная проверка, а не блокировка других клиентов на время редактирования.

Для корректной загрузки вложенных почтовых папок требуется сервер 0.9.33 или новее.
