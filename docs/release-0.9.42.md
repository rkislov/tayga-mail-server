# Tayga Mail 0.9.42 — стабильность IMAP и полная копия SQLite

При переключении папок IMAP обработчик уведомлений больше не читает контекст
одновременно с SELECT. Команды и уведомления согласованы внутри соединения;
устаревшие уведомления прежней папки отбрасываются. IDLE продолжает работать,
уведомления доходят каждому клиенту, а переполненная очередь медленного клиента
завершает его соединение для повторной синхронизации, не задерживая остальных.
Закрытие соединения отменяет ожидающие отправки и завершает пользовательскую
сессию один раз. Исправление размещено в локальной копии серверного пакета
go-imap v1.2.1 с сохранением лицензии и исходных протокольных тестов.

Новые команды `backup-full`, `verify-full`, `restore-full`, `backup-keygen`
создают зашифрованный физический снимок остановленной установки SQLite:
вся база, почта, файлы, версии, корзина, вложения, конфигурация и ключи внутри
каталога установки. SHA-256-манифест, проверка SQLite, количества записей и
ссылок на содержимое позволяют выявить повреждение и неполную копию.

Восстановление выполняется только в новый каталог, после проверки публикуется
атомарно и не запускает службы. При переносе меняются локальные пути в YAML,
настройках БД и ссылках хранилища. Создание/проверка копии не запускают миграции.
Блокировка обслуживания предотвращает запуск нового SQLite-писателя Tayga во
время полного копирования.

Проверены общий Go test suite, `go vet`, целевые race-тесты, реальные TCP-сессии
IDLE/SELECT, разделение папок и пользователей, доставка двум клиентам и закрытие.
Восстановление изолированной установки проверяет вход, ACL, календарное вложение,
историю/ключи XMPP, файлы и серверные секреты при недоступном исходном дереве;
файл 75 MiB восстанавливается без обрезания. Неверные ключи, усечённые архивы,
выход за каталог, символические ссылки и превышение лимита отклоняются.

[Инструкция резервирования](backup-full.md). Первый вариант рассчитан на
SQLite и полностью локальный каталог; публикация восстановления поддержана
на Linux/macOS. PostgreSQL/S3 и внешние сервисы требуют согласованной отдельной
процедуры. Частичные команды `backup`/`restore` сохранены. Резервная копия
закрытых OMEMO-ключей телефонов и браузеров выполняется на этих устройствах.

Изменений схемы БД в этом релизе нет. Перед обновлением нужна проверенная
копия БД/конфигурации и прежнего бинарника. Сначала запустите новую версию под
пользователем службы для создания блокировки, затем планируйте остановку для
полного бэкапа. Копия рабочего сервера, её восстановление на отдельном узле
и измерение RPO/RTO принимаются отдельно; релиз не восстанавливает ранее
утраченные исходные файлы автоматически.
