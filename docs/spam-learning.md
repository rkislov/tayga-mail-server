# Обучение Rspamd и статистика защиты (0.9.18)

Обратная связь включается автоматически, когда `spam.enabled: true`, backend — `rspamd` и `spam.learning.disabled: false` (по умолчанию). Общие операции перемещения в вебе, EWS/ActiveSync и IMAP COPY создают задания в одной транзакции с изменением письма. Внешние приложения, которые заново загружают письмо через APPEND вместо COPY, не дают серверу связи с исходным письмом и не запускают обучение.

- В Junk, Spam или `spam.folder` — `learnspam`.
- Из такой папки в обычную — `learnham`.
- Между папками спама, при первичной SMTP/Sieve-доставке и при переносе в Trash, Deleted Items или Quarantine обратной связи нет. Если Quarantine сама задана как `spam.folder`, она считается папкой спама.
- Отключение Rspamd/обучения приостанавливает очередь. Вновь выполненные перемещения во время отключения не добавляют задания.

```yaml
spam:
  enabled: true
  backend: rspamd
  url: http://127.0.0.1:11333
  folder: Junk
  learning:
    disabled: false
    url: http://127.0.0.1:11334
    password: "" # пароль контроллера с правом обучения, если требуется
```

Без `learning.url` берётся адрес сканера с заменой стандартного порта 11333 на 11334; для нестандартной схемы задайте адрес явно. Без `learning.password` используется `spam.password`. Пароль скрывается при чтении настроек и сохраняется при отправке замаскированного значения. Настройки доступны в форме Rspamd / DNSBL. Контроллер должен разрешать обучение с адреса Tayga или принимать соответствующий пароль; при настроенном Rspamd `enable_password` для обучения нужен именно он. Адрес контроллера должен быть внутренним или защищённым HTTPS. Перенаправления запросов запрещены.

Очередь хранится в SQL и переживает перезапуск. Рабочий процесс проверяет до 25 заданий каждые 5 секунд. Есть аренда задания, сериализация исправлений и до 8 попыток с задержкой. После исчерпания попыток задание отмечается failed; новое перемещение создаёт новую попытку классификации. Повторный ответ «уже обучено» учитывается отдельно. Удаление исходного письма удаляет связанное задание. Письма более 64 МиБ и отключённые аккаунты пропускаются. Завершённые задания удаляются через 7 дней; счётчики — через 90 дней.

Rspamd получает исходное MIME-письмо и адрес пользователя, но они не пишутся в диагностический журнал обучения. В журнале — ID письма, класс, результат и номер попытки. Изменение класса уже обученного письма выполняет сам Rspamd; его Bayes и Redis должны быть настроены. Наличие успешного HTTP-ответа не гарантирует немедленного изменения оценок фильтра: для работы статистического классификатора нужны образцы обоих классов.

## Статистика

**Администратор → Антиспам → Обучение и антивирус** показывает spam/ham, повторное обучение, пропуски, неудачные попытки, текущую очередь, а также clean/reject/tag/quarantine/error антивируса. Счётчики сохраняются почасово с момента установки 0.9.18. Сутки/30 дней округляются вниз до начала первого часа; это не восстановление старых журналов. Антивирусные решения считаются по получателям, а не по уникальным SMTP-сессиям. Noop не учитывается как проверка.

Администратор домена/организации/тенанта видит счётчики в пределах своих прав. Общая статистика Rspamd `/stat` и версия ClamAV доступны глобальному администратору. Если VERSION отключена, включите `EnableVersionCommand yes` в `clamd.conf` и перезапустите clamd; TCP-интерфейс должен оставаться доступным только доверенным узлам. Команда ClamAV VERSION возвращает версию движка, номер и дату **загруженной** базы. Для ICAP/exec нет универсального интерфейса версии базы: показывается отсутствие данных. Сбой обращения к контроллеру/антивирусу отображается отдельно и не подменяется нулевой версией.

API: `GET /api/v1/admin/protection/stats?period=hour|day|30d`.

Источники: [Rspamd controller endpoints](https://docs.rspamd.com/developers/controller_endpoints/), [протокол Rspamd](https://docs.rspamd.com/developers/protocol/), [права контроллера](https://docs.rspamd.com/getting-started/first-setup/), [ClamAV scanning](https://docs.clamav.net/manual/Usage/ClamdProtocol.html).
