# Миграция данных (IMAP / CalDAV / CardDAV)

Встроенный импорт с внешнего сервера в ящик пользователя. One-shot jobs в v1 (схема готова к будущему delta-sync).

## Политика доступа

Пункт **Миграция** в настройках пользователя виден только если разрешено:

1. override пользователя (`on` / `off` / `inherit`)
2. иначе override домена
3. иначе CoS `features.migration` (по умолчанию **вкл**)
4. иначе **выкл**

В UI: **Настройки → Миграция** и **Админ → Миграция IMAP/DAV** (формы IMAP / CalDAV / CardDAV).  
Админ также включает политику у домена/пользователя в **Домены и пользователи** или CoS JSON (`"migration": true`).

## API

| Метод | Назначение |
|-------|------------|
| `GET /api/v1/me` → `features.migration` | разрешено ли меню |
| `GET /api/v1/migration` | jobs |
| `POST /api/v1/migration/jobs` | создать one-shot (`kind`: `imap`\|`caldav`\|`carddav`) |
| `POST /api/v1/migration/jobs/{id}/cancel` | отмена |
| `GET /api/v1/admin/migration` | jobs тенанта |
| `PATCH …/domains/{id}` / `…/users/{id}` | `migration_enabled` |

Пароль к источнику шифруется AEAD (`server.secrets_key` или файл `secrets.key` рядом с maildir) и стирается после завершения job.

## Проверка импортированной почты

Письмо считается перенесённым после записи в maildir и добавления записи в `messages`. Для архива файл gzip сжимается; проверка повторного переноса сравнивает Message-ID и исходный RFC822-размер, а не размер gzip. Если запись в базу не удалась, задача сохраняет ошибку, а новый неиндексированный файл удаляется.

Раздел «Почта» обновляет счётчики при открытии, по кнопке обновления и раз в 15 секунд, пока он видим. Проверьте учётную запись: импорт относится к пользователю, запустившему задачу, а папка «Архив» другого пользователя остаётся пустой. Если задача осталась `running` после ручной остановки процесса, это не означает, что процесс продолжает копирование: проверьте `systemctl status tayga.service`.

## Старые кодировки и imapsync

IMAP APPEND и встроенный импорт сохраняют исходное RFC822-письмо целиком, без перекодирования. KOI8-R, Windows-1251, CP1251 и распространённые обозначения `win-1251` / `win1251` декодируются при чтении заголовков и текстовых MIME-частей. Веб-почта и FlowSync показывают текст и HTML; вложенные `multipart/alternative`, Base64 и quoted-printable учитываются при построении поискового индекса. Бинарные вложения остаются неизменными.

Проверки APPEND/FETCH подтверждают сохранение байтов, даты INTERNALDATE и флагов, отображение кириллических имён в ENVELOPE, поиск заголовков командами SEARCH/UID SEARCH с указанной кодировкой и работу кириллических имён папок. Встроенный импорт проверяет повторный запуск без дублей, включая сжатый архив.

Исправленный поисковый индекс строится при поступлении и импорте писем; существующий индекс автоматически не перестраивается. Просмотр уже сохранённых писем использует новый декодер сразу после обновления.

Неизвестная или неверно указанная кодировка не является причиной отказа в APPEND. Оригинал сохраняется, однако правильное отображение нельзя гарантировать без корректного MIME-описания. По одному ответу чужого сервера `NO Append mail error` установить причину невозможно: для диагностики нужны полный ответ сервера и соответствующая запись его журнала.
