# Tayga Mail Server 0.10.7

Добавлена поддержка полей бесед Outlook, исправлено его падение при синхронизации календаря и ускорено открытие больших писем Thunderbird. Плагин Thunderbird остаётся версии 2.4.0.

## Outlook: падение при чтении календаря

В отчёте Outlook 16.114.4 от 6 ноября падение происходило в `EWS::CStartTimeZone::Create` → `EWS::CTimeZoneDefinition` → `CFXMLCreateStringByUnescapingEntities`. Клиент без проверки передавал отсутствующий атрибут Name в CoreFoundation. Tayga теперь отдаёт непустые Id и Name в StartTimeZone и EndTimeZone, включая UTC и Windows-названия часовых поясов. Исправляются также старые закэшированные ответы SyncFolderItems при точном повторе запроса с прежним ключом.

Точечная сборка с этим исправлением была установлена перед выпуском; пользователь подтвердил, что Outlook запускается и синхронизируется без падения.

## Outlook: цепочки писем

GetItem и FindItem с запросом свойств беседы возвращают ConversationId, ConversationIndex и ConversationTopic. Группировка опирается на Message-ID/References/In-Reply-To, а не на совпадение темы. Исходная тема и связи восстанавливаются между Входящими, Отправленными и архивными папками одного пользователя. Оригинальный валидный Thread-Index/Thread-Topic сохраняется; при отсутствии индекса строится бинарный индекс формата MS-OXOMSG. Поддерживаются ответы только с In-Reply-To, ссылки с переносами строк, отсутствующий предок и ошибочный исходный Thread-Index.

Структурированная отправка Message через EWS сохраняет References, In-Reply-To, Thread-Index и Thread-Topic. Проверяются границы заголовков, чтобы не допускать их внедрение. Поиск предков изолирован по владельцу, а миграция 066 добавляет индекс по RFC Message-ID. Обычные IdOnly-запросы Thunderbird не запускают дополнительное построение бесед.

В Outlook должен быть включён режим бесед. Для старой локально закэшированной переписки может понадобиться обновление нужной папки: отображение этих писем зависит от того, перечитал ли клиент их новые свойства. Поля бесед протестированы на сервере; визуальное объединение в пользовательском Outlook требует клиентской проверки. Расширенные операции FindConversation/GetConversationItems/ApplyConversationAction этим выпуском не реализованы.

## Thunderbird: большие письма

Для одиночного GetItem используется уже сформированный SOAP-ответ без повторного разбора и кодирования всего base64. Сбор диагностического результата заканчивается после единственного ResponseCode, не читая MIME повторно. Для пакетов из нескольких элементов сохраняется проверка последующих ошибок.

В локальном серверном benchmark (Apple M4, GOMAXPROCS=2, три итерации) обработка 32-МБ MIME ускорилась с 582 до 30 мс. Общий объём выделений памяти снизился примерно с 972 до 436 МБ на операцию. Это выделения за операцию, не размер одновременно занятой памяти; измерение не включает передачу по внешней сети.

В настоящем Thunderbird 159 с изолированным профилем письмо с 32-МБ MIME и 24-МБ вложением отобразилось при первом открытии за 408–474 мс, повторно — за 138–196 мс в двух локальных прогонах. Тело и вложение проверены, повторное открытие не вызвало повторной загрузки MIME. Сетевое время на рабочем сервере зависит от соединения и размера письма.

## Проверки

Выполнены полный Go-прогон, целевые race-тесты, проверка SOAP/MIME на сохранение исходных байтов и ошибки многопозиционного пакета, тесты миграции индекса, свойств беседы, разграничения доступа и часовых поясов. Нативный Thunderbird E2E проверяет отображение большого письма, извлечение 24-МБ вложения, кэш повторного открытия, цепочки, календарь, задачи и отправку.
