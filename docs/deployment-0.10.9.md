# Установка исправления отправленных бесед 0.10.9

9 ноября 2026 года опубликован v0.10.9, коммит feb6195. GitHub Actions Release 42665734623 завершился успешно. Восемь контрольных сумм (семь серверных архивов и Thunderbird XPI 2.5.0) сопоставлены с GitHub asset digests. Содержимое каждого файла локального установленного XPI совпадает с опубликованным XPI.

## Совместимость с установленной сборкой

До обновления mail.kislovs.ru использовал `0.10.8+mattermost.20`. Её исходники из отдельного рабочего каталога воспроизвели бинарник побайтно: SHA256 `a5db3e93ad3351c3c28457c17b86f644fc3ceb7a9c4afeebb99fc1c6875759be` совпал с работающим процессом. Исправление бесед объединено с этой сборкой в отдельном снимке исходников без изменения чужого рабочего каталога. Сохранены изменения Mattermost, сессий, push и календарных писем ActiveSync. Эта серверная установка отличается от обычного архива GitHub наличием уже работавших до обновления изменений Mattermost.

Установлен процесс `tayga-mail 0.10.9+mattermost.20 (feb6195+mattermost.20) built 2026-11-09T17:33:17Z`. SHA256 `cdedd291e33a64b7dc2b2ce7b1f3724716ee666ae50a651b7a903f37830a6176`, PID при проверке 588302. Служба active/running, healthz=ok, readyz=ready. Конфигурация не изменилась. ## Проверки

Пройдены полный Go-прогон основной версии, полный flowsync-прогон, целевые race-тесты и 61 JavaScript-тест расширения. В интеграционном снимке отдельно пройдены тесты flowsync и Mattermost. Нативный Thunderbird E2E проверил объединение Inbox/Sent в одной виртуальной цепочке без копирования сообщений, открытие этой папки штатной командой плагина, большое письмо и вложение, отправку, календарь, задачи и перезапуск клиента.

Диагностика рабочей базы выполнялась с `mode=ro`. Из семи отправленных сообщений, ссылающихся на текущие входящие, до исправления четыре получали общую беседу с входящими, после исправления — все семь. В журнал выводились только количества и признаки структуры ссылок, без тем и содержимого писем.

Для перечитывания EWS-свойств обновлена служебная ревизия метаданных 1035 писем в Inbox/Sent одной учётной записи. Исходные значения сохранены в закрытом файле `mail-metadata-before.json` в резервном каталоге. В одной транзакции проверено, что флаги, пути, темы и Message-ID всех этих писем остались прежними. Сброс синхронизации не выполнялся.

В рабочий Thunderbird установлен XPI 2.5.0. Открытая виртуальная папка показала 1036 писем: 132 входящих и 904 отправленных. Разница с числом обновлённых EWS-метаданных связана с новым входящим письмом во время проверки. Обычные папки не заменялись.

В Outlook после обычной синхронизации старое отображение из локального кэша ещё не подтвердило наличие собственных ответов в раскрытой входящей цепочке. Очистка локальных кэшей Inbox/Sent пока не выполнялась: она требует отдельного согласия из-за предупреждения Outlook о потере несинхронизированных локальных элементов. Не следует считать эту визуальную проверку завершённой по одному совпадению серверных ConversationId.

На физическом iPhone визуальная проверка не выполнялась. Протокольные тесты проверяют общие с EWS идентификаторы, бинарную WBXML-передачу и сохранение ссылок ответа/единственной Sent-копии при ReplaceMime и повторе отправки. Для отображения полного обсуждения нужны настройки группировки приложения «Почта».
