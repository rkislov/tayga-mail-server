# Агенты TMS 1.3.0

Встроенный интерфейс TMS использует структуру навигации Mattermost Agents:
каталог с поиском, личная история по агентам, диалог, навыки и настройки.
Это самостоятельная реализация TMS, а не оригинальный плагин `mattermost-ai`.
Она доступна в веб-интерфейсе TMS и в настольном клиенте, открывающем этот
интерфейс. Нативное приложение Mattermost для iPhone не получает новый экран
Agents от серверного обновления.

[Пользователю](user-guide.md) · [Администратору домена](domain-admin-guide.md) ·
[Администратору сервера](admin-guide.md).

В форме подключения нажмите **Проверить подключение** после ввода URL и ключа.
Выберите модель из каталога, который вернул провайдер. Ollama показывает
установленные модели. Для сохранённого подключения можно использовать
имеющийся ключ, оставив поле пустым. Ручной ввод идентификатора доступен,
если у совместимого API нет каталога. Генерацию ответа проверьте в диалоге.

Каталоги OpenAI, DeepSeek и локального Ollama на порту 11434 доступны сразу.
Для своего сервера Ollama или совместимого API администратор Tayga указывает
разрешённые базовые URL через запятую в переменной службы
`TAYGA_AGENT_MODEL_CATALOG_URLS`, например `https://models.example.com/v1`.

## Настройка DeepSeek

1. Войдите под администратором нужного домена. Откройте **Агенты → Настройки →
   Подключить модель**.
2. Выберите **DeepSeek**. Предустановлены URL `https://api.deepseek.com` и модель
   `deepseek-flash`. Каталог позволяет выбрать другую модель провайдера.
3. Введите собственный API-ключ, полученный в
   [DeepSeek Platform](https://platform.deepseek.com/). Ключ не нужно отправлять
   в чат. По умолчанию режим рассуждений выключен; его можно включить в форме.
4. Сохраните подключение, создайте агента, выберите модель и задайте инструкции.
   После включения агент появляется в каталоге пользователей этого домена.
5. Начните диалог из каталога или кнопкой `+` рядом с агентом.

Запросы отправляются с сервера TMS на `/chat/completions`, с Bearer-ключом и
параметром `thinking.type`, соответствующим настройке. В истории сохраняется
финальный ответ, без `reasoning_content`. При обычном ответе лимит генерации
4096 токенов; при включённых рассуждениях — 16384, включая рассуждения.
Общий тайм-аут обращения к модели — 120 секунд. Если провайдер не ответил,
текст запроса не добавляется в сохранённую историю и его можно повторить.

Параметры сверены с [официальной документацией DeepSeek](https://api-docs.deepseek.com/)
и [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/).
Список моделей может изменяться. Изолированные тесты проверяют протокол;
оплачиваемый запрос к реальному DeepSeek без ключа оператора не выполнялся.

Для другого OpenAI-совместимого API выберите соответствующий тип и укажите
базовый URL, идентификатор модели и ключ. HTTPS обязателен, кроме HTTP на
`localhost`, `127.0.0.1` и `::1`. Перенаправления не выполняются, чтобы не
передавать ключ и сообщения другому адресу. Вариант DeepSeek принимает только
его официальный адрес (также допустим суффикс `/v1`).

## Ollama — нативный API

В форме подключения выберите **Ollama**. Адрес по умолчанию —
`http://127.0.0.1:11434`. Это loopback **сервера TMS**, а не компьютера,
на котором открыт браузер. Укажите имя уже установленной модели из `ollama list`.
Модель автоматически не выбирается и не скачивается. Установка/запуск Ollama
в эту настройку не входит. Для удалённого движка укажите его доступный адрес.

TMS обращается к нативному `/api/chat` с историей только текущего диалога,
`stream: false` и ограничением `options.num_predict: 4096`. Если базовый адрес
заканчивается на `/api`, второй `/api` не добавляется. В историю записывается
финальный `message.content`, без поля рассуждений. Незавершённый ответ не
сохраняется как успешный. Локальный Ollama не требует API-ключа; для защищённого
прокси или облачного подключения ключ можно указать в форме.

HTTP разрешён для loopback и числовых частных IP-адресов RFC1918/ULA,
например `http://192.168.1.20:11434` или `http://[fd00::1]:11434`.
Для публичного адреса и DNS-имени удалённого сервера используйте HTTPS.
Link-local адреса служб метаданных и публичный HTTP не разрешаются. Проверка
TLS и запрет перенаправлений сохраняются. Разрешение частного HTTP относится
только к нативному типу Ollama; ограничения совместимого API не расширяются.

Протокол: [официальный Ollama Chat API](https://docs.ollama.com/api/chat).
Также можно использовать прежний совместимый тип с `/v1`, если нужен именно
[OpenAI-совместимый протокол Ollama](https://docs.ollama.com/api/openai-compatibility).

## OpenAI (ChatGPT)

Выберите **OpenAI (ChatGPT)**, введите ключ OpenAI API и модель, доступную этому
ключу. Предустановлен официальный адрес `https://api.openai.com/v1`;
в подсказках предлагаются `gpt-6.2-sol` и `gpt-6-luna`, но идентификатор можно
отредактировать. Используется API-ключ из OpenAI Platform, а не браузерная сессия
ChatGPT. При переключении провайдера поле нового ключа очищается.

Запрос отправляется на `/chat/completions` с `max_completion_tokens: 16384`
(включая рассуждения) и `store: false`. Устаревший `max_tokens` этому типу не
передаётся. Общее ограничение времени и проверка сессии остаются прежними.
Не все функции веб-приложения ChatGPT входят в этот текстовый API-коннектор:
поиск выполняется инструментом TMS через отдельный поисковый сервис; загрузки файлов модели пока нет.

[Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create),
[каталог моделей OpenAI](https://developers.openai.com/api/docs/models).
Реальный запрос требует действительного ключа; протокольные тесты используют
синтетические ответы без обращения к оплачиваемому сервису.

## Разделение данных

- Конфигурация провайдеров, агентов и навыков привязана к паре **тенант + домен**.
  Автоматического наследования ключей от сервера или соседних доменов нет.
  Администратор редактирует настройки домена своей текущей учётной записи.
- История дополнительно привязана к внутреннему ID пользователя. Переданный
  клиентом ID чужого диалога не даёт доступа к нему, включая запрос отправки
  сообщения и удаление. Параметры `tenant_id`, `domain_id`, `user_id` клиента
  не выбирают область данных.
- Каталог пользователей содержит имена и описания доступных агентов/навыков,
  без ключей провайдеров и системных инструкций. Ключ не возвращается даже в
  администраторской форме: показывается только признак его наличия. Пустое
  поле сохраняет прежний ключ только для того же ID, адреса и типа провайдера.
  Для удаления ключа удалите неиспользуемое подключение и создайте его заново.
- Пользователи не получают почту, историю, подключения, планы и инструменты
  владельца существующего aiagent-бота. Этот продукт работает независимо от
  его конфигурации. Навык здесь — дополнительные инструкции. Доступ к инструментам
  отдельно разрешается в настройках агента. Произвольный код не исполняется.
- При выходе или смене токена интерфейс очищает состояние и отбрасывает
  запоздавшие ответы. Сервер проверяет сессию повторно перед сохранением ответа
  модели, а также проверяет, что конфигурация и политика домена не изменились.
- Изменения и результат генерации отмечаются в серверном журнале с ID области,
  пользователя и диалога; текст сообщений, инструкции и ключи туда не пишутся.

Сам текст текущего диалога и инструкции выбранного агента отправляются
настроенному провайдеру. Другие диалоги в запрос не включаются. При разрешённых
почтовых инструментах найденные письма текущего пользователя передаются модели;
для локальной обработки выбирайте собственный Ollama. Поисковые запросы уходят
через настроенный поисковый сервис.

## Хранение и границы реализации

Данные находятся в таблице `settings` основного хранилища TMS под ключами
`mattermost.agents.config:<scope hash>` и
`mattermost.agents.history:<scope+user hash>`. Они входят в резервную копию
основной БД. Ключ провайдера хранится на сервере в этой конфигурации; отдельного
шифрования поля нет, поэтому файл/доступ к БД и резервные копии должны быть
защищены так же, как остальные серверные секреты. Удаление пользователя пока
не удаляет автоматически связанные записи Agents.

Один пользователь может хранить до 100 диалогов, до 200 сообщений в диалоге;
общая запись истории ограничена 16 МиБ. Поддерживается не более четырёх
одновременных генераций на процесс. Одновременная отправка в один диалог
отклоняется, незавершённая заявка после аварии истекает через 150 секунд.
Изменения настроек защищены от перезаписи устаревшей формой.

Блокировка истории рассчитана на один процесс TMS. Несколько записывающих
экземпляров на общей БД требуют транзакционного хранилища диалогов вместо
текущего read/modify/write настроек.

Пока нет потоковой выдачи ответа, MCP/OAuth, загрузки файлов в модель,
произвольного исполнения кода, настроек доступа к отдельным агентам внутри одного
домена, синхронизации с личными сообщениями бота и полной совместимости с API
оригинального плагина Agents. Навыки не исполняют действия. Оригинальный плагин
Agents и существующий aiagent-бот не устанавливаются и не перенастраиваются
этим изменением. Платная лицензия Mattermost не требуется.

## Проверка

```sh
go test -race ./internal/mattermost -run '^TestAgents' -count=1
cd frontend && npm run test:chat && npm run build
```

Покрыты границы двух тенантов и соседних доменов, чужая история, скрытие
секретов, инструкции/навыки в запросе, отзыв сессии во время генерации,
защита от двойной отправки, конфликт версии настроек и запрет перенаправления.
Протоколы DeepSeek и OpenAI проверяются с синтетическими ключами и ответами,
Ollama — через локальный HTTP-стенд с нативным ответом. Тестируются также
ограничения адресов и очистка ключа при смене провайдера.

Опциональный браузерный стенд с синтетическими аккаунтами и моделью:

```sh
TMS_TEST_AGENTS_BROWSER=1 go test ./internal/mattermost \
  -run '^TestAgentsBrowserStand$' -v -count=1 -timeout 12m
```

Он слушает только `127.0.0.1:59865` и останавливается через 10 минут. Не
подключайте его к публичному reverse proxy: страница содержит тестовый токен.

## Общая история с Mattermost и инструменты

После обновления доступные агенты регистрируются как боты своего домена без
пароля и служебного токена. В Mattermost найдите агента по имени в личных
сообщениях либо выполните `/agents`. Диалог веба соответствует отдельной ветке
личного чата: сообщения и ответы доступны с обеих сторон. Сообщение в DM без
указания ветки продолжает последний диалог. Ответы на телефоне доставляются
асинхронно обычными сообщениями/уведомлениями. Веб проверяет обновления раз в
4 секунды. Интерфейсы различаются, история и контекст общие.

Старые веб-истории переносятся в собственную ветку при продолжении разговора.
«Убрать из списка» скрывает диалог веба, оставляя сообщения Mattermost. Отдельные
личные чаты других пользователей не включаются в контекст модели.

Скрепка добавляет до пяти файлов в сообщение. Микрофон записывает голосовое
сообщение продолжительностью до трёх минут. Остановите запись, проверьте
вложение в черновике и нажмите **Отправить**. Запись можно прослушать в
диалоге. До 16 КиБ текста на файл и 48 КиБ на запрос передаётся модели из
поддерживаемых текстовых вложений UTF-8. Голосовые и другие бинарные файлы
сохраняются в общей ветке и доступны для скачивания. Расшифровки аудио нет.

В настройках агента администратор отдельно разрешает веб-поиск, поиск/чтение
почты, подготовку писем, чтение каналов и подготовку сообщений. По умолчанию
инструменты выключены. Почта доступна только из собственного ящика пользователя,
без делегированных ящиков. Чтение тела ограничено письмами до 1 МиБ; в модель
передаётся до 20 000 символов текста без вложений. Поиск чата ограничен последними
200 сообщениями выбранного доступного канала и возвращает до 10 совпадений.

Поиск настраивается в «Агенты → Настройки → Веб-поиск»: Brave Search API (ключ)
или SearXNG (JSON API). Для собственного сервиса без Docker есть
`scripts/agents/install-searxng.sh`: pinned исходники SearXNG, systemd,
`http://127.0.0.1:18788`, без публичного reverse proxy. Ключ SearXNG не нужен.
Сервис и параметры домена включаются отдельно. В диалоге пользователь включает
кнопку **Веб-поиск** под полем сообщения или `/agent-web on`; `/agent-web off` выключает, `status` показывает
сохранённое состояние. Модели передаётся текущий статус каждого запроса.

Отправка всегда двухшаговая. Модель создаёт черновик с точным адресатом и текстом;
пользователь подтверждает в веб-карточке, кнопкой сообщения Mattermost или
`/agent-confirm ID` в той же личной ветке. Подтверждение действует 10 минут,
привязано к пользователю/диалогу/версии настроек, не принимает изменения текста
от клиента и используется один раз. После неоднозначной ошибки проверьте
исходящие, прежде чем готовить новое письмо. Письма проходят штатный конвейер
отправки, включая ограничения отправителя и DLP. Заголовки писем и сообщения
отправляются от текущего пользователя. Настройки и права владельца бота не
используются. MCP и произвольные внешние инструменты в эту реализацию не входят.

### Отдельный маршрут OpenAI

При необходимости задайте службе Tayga переменную `TAYGA_OPENAI_RELAY=127.0.0.1:18790`. На этом порту должен слушать локальный TCP-туннель до `api.openai.com:443`. Проверка сертификата и имя хоста OpenAI сохраняются. Параметр применяется к встроенному подключению OpenAI. Ответ об исчерпании кредита указывает на баланс API-аккаунта.
