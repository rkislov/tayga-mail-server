# Архив почты и быстрый поиск

Кратко на русском: как устроены папка **Архив** (сжатие тел писем) и **полнотекстовый поиск**, что нужно для включения и как пользоваться.

English summary: [architecture.md — Archive mailbox / Mail search](./architecture.md#archive-mailbox).

## Настройка

Отдельной секции YAML для Archive/поиска **нет** — всё работает на штатном хранилище почты и БД.

1. **Миграция БД** — при старте `tayga` применяется миграция `018_mail_archive_search` (SQLite и PostgreSQL):
   - колонки метаданных в `messages`: `subject`, `from_addr`, `to_addr`, `date_hdr`, `archived`;
   - индекс FTS: SQLite — виртуальная таблица `message_fts` (FTS5); Postgres — `message_search` (`tsvector` + GIN).
2. **Maildir** — как обычно, `mailstore.root` в bootstrap YAML (см. `configs/tayga.example.yaml`). Сжатые письма лежат в `.Archive/` как `*.eml.gz`.
3. **Перезапуск / обновление** — после обновления бинарника достаточно обычного старта: миграция и папка Archive создаются автоматически при первом обращении к списку ящиков в веб-UI (или при доставке/архивации).
4. **Внешний поисковый движок не нужен** — Elasticsearch / Meilisearch не используются. Для SQLite FTS5 доступен при `CGO_ENABLED=0` (modernc.org/sqlite).

Проверка:

- в веб-интерфейсе в списке папок появилась **Archive**;
- кнопка **Архив** на карточке письма;
- поле поиска в панели списка писем;
- API: `GET /api/v1/mail/search?q=…`, `POST /api/v1/mail/messages/{id}/archive`.

## Как работает архив

### Назначение

Папка **Archive** — системная (наравне с Sent, Drafts, Trash, Junk). Письма в ней хранятся **сжатыми gzip**, а тема/отправитель/получатель/дата остаются в БД, чтобы список открывался без чтения тела с диска.

### Когда срабатывает сжатие

| Действие | Результат |
|----------|-----------|
| Кнопка **Архив** в веб-UI | `POST …/messages/{id}/archive` |
| Перенос в папку Archive (`POST …/move` с `mailbox_id` Archive) | то же сжатие |
| Доставка сразу в папку Archive (IMAP APPEND / Sieve fileinto `Archive`) | файл сразу пишется как `.eml.gz` |

### Алгоритм при архивации

1. Читается исходный RFC822 с диска (при необходимости — с gunzip, если уже был `.gz`).
2. Текст тела извлекается для FTS (см. ниже).
3. Сообщение целиком сжимается gzip → файл в `.Archive/cur/…eml.gz`.
4. Обновляются `file_path`, `size` (сжатый размер), `archived=1`, метаданные заголовков.
5. Старый несжатый файл удаляется.

### Чтение (IMAP / HTTP / FlowSync)

`mailstore.Read` прозрачно разжимает файл, если путь оканчивается на `.gz` или содержимое начинается с magic `1f 8b`. Клиенты получают обычный RFC822; менять IMAP FETCH не нужно.

### Разархивация

Перенос письма **из** Archive в другую папку: файл разжимается в обычный Maildir-файл, флаг `archived` сбрасывается.

### Список писем

`GET …/mailboxes/{id}/messages` отдаёт `from` / `to` / `subject` / `date` из колонок БД. Если у старых писем метаданные ещё пустые — при первом списке выполняется ленивый backfill (чтение с диска + запись в БД и FTS). Полное тело — только при `GET …/messages/{id}`.

## Как работает поиск

### Слои индекса

| Слой | Роль |
|------|------|
| Колонки `subject`, `from_addr`, `to_addr` | быстрые фильтры `from:`, `to:`, `subject:` |
| SQLite FTS5 `message_fts` | полнотекст + ранжирование `bm25` |
| Postgres `message_search` | `tsvector` + GIN, ранжирование `ts_rank_cd` |

### Индексация (при доставке / архиве)

1. Разбор MIME → предпочтение `text/plain`; если только HTML — снятие тегов.
2. Нормализация: нижний регистр (тело для FTS).
3. Upsert в FTS; при окончательном удалении письма — удаление строки индекса.

Вложения (бинарники) **не** индексируются; имена из заголовков могут попасть в текст документа, если присутствуют в разбираемой части.

### Запрос

`GET /api/v1/mail/search?q=&mailbox_id=&limit=`

1. Разбор `q`: префиксы `from:`, `to:`, `subject:` + свободный текст.
2. Префиксы → `LIKE` по колонкам метаданных.
3. Остальные слова → FTS (`MATCH` / `plainto_tsquery`), семантика **AND**.
4. Область: только ящики текущего пользователя; опционально `mailbox_id`.
5. Ответ: id + метаданные + короткий snippet; **без** полного тела (тело — при открытии письма).

Примеры:

```text
отчёт
from:boss@example.com бюджет
subject:счёт 2024
to:finance@example.com invoice
```

### Веб-UI

- Поле поиска в панели списка писем — результаты вместо текущего folder list.
- Escape очищает запрос.
- Клик по результату открывает письмо обычным `GET /messages/{id}` (с gunzip при необходимости).

## API (сводка)

| Метод | Назначение |
|-------|------------|
| `GET /api/v1/mail/search?q=` | поиск |
| `POST /api/v1/mail/messages/{id}/archive` | в Архив + gzip |
| `POST /api/v1/mail/messages/{id}/move` | перенос; в Archive — сжатие, из Archive — разжатие |
| `GET /api/v1/mail/mailboxes/{id}/messages` | список по метаданным БД |

## Ограничения этой версии

- Отдельный wire-протокол IMAP SEARCH не менялся (поиск через веб/API; IMAP FETCH по-прежнему через gunzip).
- Нет внешнего поиска и опечаткоустойчивости (trigram) — отложено.
- Бинарные вложения в индекс не входят.
