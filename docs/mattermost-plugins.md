# Плагины и интеграции Mattermost — контракт API 12

TMS использует собственный чат и RPC-хост плагинов на официальном SDK `github.com/mattermost/mattermost/server/public v0.6.1`. Целевая версия совместимости — **12.0.0**. Её используют discovery, HTTP-заголовок, приветствие WebSocket и `GetServerVersion` Plugin API. Это версия протокольного контракта, отдельная от номера выпуска Tayga. Полный сервер и веб-клиент Mattermost не включены в TMS; неподдерживаемые методы по-прежнему возвращают явный отказ, включая методы SDK для более поздних версий.

## Что проверено 19 ноября 2026

- **GitHub Plugin 3.0.0** — установка официального пакета, активация через RPC, создание scoped-бота и его аватара, `/github help`, доставка ответа как ephemeral-сообщения, деактивация. Проверено на macOS arm64 и Linux amd64. В [манифесте 3.0.0](https://github.com/mattermost/mattermost-plugin-github/blob/v3.0.0/plugin.json) указан минимум Mattermost 12.0.0.
- **GitLab Plugin 1.13.1** — те же этапы и `/gitlab help`, macOS arm64 и Linux amd64. [Официальный пакет](https://github.com/mattermost/mattermost-plugin-gitlab/releases/tag/v1.13.1).
- **BigBlueButton, пакет v4.5.0** — установка, активация, `/bbb`, сохранённая карточка приглашения и деактивация на Linux amd64. Внутри этого [опубликованного пакета](https://github.com/blindsidenetworks/mattermost-plugin-bigbluebutton/releases/tag/v4.5.0) манифест содержит версию 4.4.0; проверка фиксирует обе версии. Внешний BBB и запись конференций не запускались. Для macOS arm64 нативного пакета нет; опубликованный macOS amd64-пакет в пробе под Rosetta не завершил RPC-запуск за отведённое время и не принят.
- **Redmine Messenger и Jenkins** — проверены контракты входящих вебхуков: URL-encoded `payload` и JSON, текст и вложенные карточки, привязка к одному каналу, запрет смены канала и отзыв URL. Это компоненты [Redmine](https://github.com/AlphaNodes/redmine_messenger) и [Jenkins](https://github.com/jenkinsci/mattermost-plugin), использующие вебхуки TMS. Их установка не выполняется загрузкой пакета в хост TMS.
- **Zabbix** — проверены REST-сценарии поиска команды/канала по имени, создание карточки проблемы и ответа в треде по контракту официального [media type Mattermost](https://github.com/zabbix/zabbix/blob/master/templates/media/mattermost/media_mattermost.yaml). Принимался профиль `send_mode=event`. Профиль `alarm` требует `PUT /posts/{id}` для правки исходной карточки; этот метод пока возвращает 501. Работа самого Zabbix и полного скрипта его media type не проверена.
- **Jitsi** — сохраняется встроенный [путь TMS](vks.md) через `/meet` и действие канала, ранее принятый пользователем на iPhone. Он не подменяет проверку стороннего Marketplace-пакета Jitsi.

Для GitHub/GitLab пока не приняты OAuth с рабочими учётными записями, подписки на репозитории, настоящие внешние вебхуки, создание задач/MR/PR и веб-интерфейс плагинов. Для BBB не приняты присоединение к работающему серверу, звук/видео и записи. Смена контракта на 12 не подтверждает полную совместимость всех этих сценариев. Новая ручная матрица штатного Mattermost на iPhone и MattCha после изменения версии контракта остаётся отдельной проверкой.

## Изоляция и аватары

Хост экземпляра плагина получает конкретные тенант и домен. Конфигурация, KV, боты и включение разделяются по scope. Поиск пользователей по ID/email/username, выбор участников и личных каналов ограничены этой областью. Канал для доменного SDK должен принадлежать создателю из этого домена; общий канал другого домена не становится доступен плагину только из-за членства пользователя. Пользовательские возможности чата сохраняют свою отдельную модель прав.

События плагина несут домен и фильтруются WebSocket-получателем, в том числе для соседних доменов одного тенанта. Плагин может менять аватар только собственного scoped-бота. Изображения проверяются по размеру и формату, нормализуются в PNG и сохраняются через штатное хранилище аватаров TMS. SVG/HTML, слишком большие изображения, аватары людей и ботов другого плагина отклоняются. Плагинам по умолчанию передаётся `EnableDiagnostics=false`.

## Повторяемый стенд

Обычный `go test ./...` не скачивает Marketplace-пакеты. Отдельная проверка использует зафиксированные URL, версии и SHA-256 из [marketplace.json](../internal/mmplugins/testdata/marketplace.json). У GitHub/GitLab SHA совпадают с digest GitHub Releases; старые пакеты BBB не имеют опубликованного digest, для них закреплён хеш полученного официального артефакта. Это фиксация содержимого, не проверка подписи издателя.

Для нативной платформы:

```sh
python3 scripts/fetch-mattermost-plugin-fixtures.py --output /tmp/tms-mmplugins
TMS_TEST_PLUGIN_BUNDLES=/tmp/tms-mmplugins CGO_ENABLED=0 go test ./internal/mmplugins -run TestMarketplacePluginBundles -count=1 -v -timeout 2m
```

Для Linux amd64 можно выбрать `--platform linux-amd64` и запустить тест на таком узле. [Workflow приёмки](../.github/workflows/mattermost-plugins.yml) выполняет этот сценарий на Ubuntu при изменении SDK/хоста. Перед установкой и исполнением тест повторно проверяет хеш, ID и версию манифеста. Подмена пакета не проходит проверку.

Локальный Linux-прогон 19 ноября выполнен в одноразовом контейнере с `--network none`, корневой ФС только для чтения и временным исполняемым `/tmp`. Плагины обращаются к тестовому loopback-сервису; рабочих OAuth-токенов и внешних систем в стенде нет. Рабочий сервер mail.kislovs.ru в этом этапе не изменялся.

## Подключение вебхуков

Включите API и интеграции в нужной области управления. Авторизованный создатель канала может создать URL через `POST /api/v4/hooks/incoming` с `channel_id`, `display_name`, `description`. Ответ содержит ID; адрес отправки — `https://<TMS>/hooks/<id>`. URL является секретом доступа к одному каналу. Для разных каналов нужны отдельные URL. Redmine/Jenkins настраиваются на стороне соответствующего сервиса.

Для Zabbix в проверенном профиле используйте `send_mode=event`. Имя команды берётся из `GET /api/v4/users/me/teams` (`name` вида `tms-…`); значение `send_to` — `<team-name>/#<channel-name>` или ID доступного канала. В сценариях проверки использовался действующий API-токен тестового пользователя; отдельная выдача и отзыв долгоживущих bot/PAT-токенов для эксплуатации ещё требуют приёмки.
