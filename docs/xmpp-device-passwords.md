# Пароли устройств XMPP

В профиле пользователя, в блоке безопасности, доступен раздел **«Устройства XMPP»**. Открыть его можно и из настроек шифрования чата кнопкой **«Пароли и доступ устройств»**.

## Подключение и переход

1. Нажмите «Создать пароль устройства» и задайте узнаваемое имя, например «Monal · iPhone».
2. Скопируйте пароль. Он показывается только один раз и не сохраняется в браузере. Если окно закрыто до копирования, отзовите этот пароль и создайте новый.
3. В настройках существующего аккаунта XMPP замените пароль. Логин, сервер и порт оставьте прежними; используйте TLS/STARTTLS. Удалять аккаунт или ключи OMEMO не требуется.
4. Подключите приложение и обновите список в профиле. Появятся время входа и активное соединение.
5. Повторите для остальных клиентов. После проверки хотя бы одного нового пароля можно включить **«Только пароли устройств для XMPP»**.

По умолчанию сохраняется переходный режим: обычный пароль и общие OAuth-токены продолжают работать в XMPP с прежними ограничениями MFA. Строгий режим включается только пользователем. Он закрывает старые соединения, запрещает их восстановление и удаляет push-регистрации, не связанные с паролем устройства. После подключения новым паролем приложение заново регистрирует push. Веб-чат, веб-вход, почтовые протоколы, FlowSync, LDAP и passkey этот переключатель не меняет.

Пароль устройства принимается только на границе SASL PLAIN в защищённом XMPP-соединении. Его нельзя использовать для входа в веб, IMAP, SMTP, POP3, EWS, ActiveSync, CalDAV или CardDAV. LDAP не получает секреты этого формата. В строгом режиме общие OAuth-токены также не могут обойти ограничение XMPP.

## Отключение, отзыв и потеря устройства

- **Отключить** закрывает выбранное живое соединение и запрещает восстановление именно этого потока. Клиент может выполнить новый вход с тем же действующим паролем.
- **Отозвать** окончательно блокирует пароль, закрывает все соединения с ним, удаляет сохранённые потоки и связанные push-регистрации вместе с очередью. Остальные пароли и веб-сессия сохраняются. Пароль нельзя восстановить: для повторного подключения создайте новый.
- При потере устройства отдельно отзовите его **ключ OMEMO** в настройках шифрования чата. Ключ шифрования и пароль доступа имеют разные назначения; автоматическое сопоставление по названию ресурса не выполняется.

Один пароль — один логический допуск клиента, а не привязка к оборудованию. Если пароль скопирован в несколько приложений, отзыв отключит все эти приложения. Пока разрешён обычный пароль, знающий его клиент может войти этим способом; для полного перехода включите ограничение после замены паролей. Отзыв доступа не стирает локальную историю и уже загруженные файлы. Уже отправленное push-уведомление и завершённую операцию отозвать невозможно.

В списках есть поиск и пагинация. Возвращаются все действующие пароли (до 50) и последние отозванные, суммарно до 100 записей. Список соединений содержит только XMPP-сессии текущего пользователя в активном процессе сервера. Для многопроцессной active-active топологии потребуется отдельное распространение отзыва между узлами; эта реализация рассчитана на один активный процесс Tayga, включая active-passive развёртывание.

## Хранение и проверка

Миграция 057 добавляет `xmpp_device_passwords`, `xmpp_auth_policy` и `credential_id` в push-регистрации. Секрет содержит 256 случайных бит; хранится SHA-256 полного значения. Хеш не выдаётся API и очищается при отзыве, метаданные остаются для отображения статуса. API имеет `Cache-Control: no-store`; браузер очищает одноразовое окно при закрытии, выходе и смене аккаунта.

Регистрация соединения повторно проверяет доступ под блокировкой пользователя: аутентификация, начатая перед отзывом, не может зарегистрировать соединение после него. Возобновление SM требует того же пароля устройства, которым был открыт исходный поток. Сохранение потока после обрыва и регистрация push проверяют отзыв повторно. Статус отзыва и политика входа сохраняются в БД после перезапуска; SM-потоки остаются краткоживущими в памяти, как и ранее.

Проверки:

- `go test ./...` — полный набор Go-тестов.
- `go test -race ./internal/xmpp ./internal/httpapi ./internal/storage -run 'Test(XMPPDevice|OwnXMPP|Resume|Push)'` — реальные TCP-входы, восстановление с правильным паролем, отказ с другим, отзыв активного и отключённого клиента, поздняя регистрация push/потока, параллельный вход и отзыв, изоляция владельцев, неизменность почтового и веб-входа.
- `TAYGA_TEST_BOOKING_POSTGRES_DSN=postgres://... go test -race ./internal/storage -run TestXMPPDevice` — те же транзакции в отдельной временной схеме PostgreSQL, откат при ошибке удаления push, лимит при конкурирующем создании. Без переменной используется SQLite.
- `TMS_URL=http://127.0.0.1:PORT node scripts/check-xmpp-devices.mjs` — отдельный чистый локальный сервер с тестовым `admin@example.com / changeme`: реальный API и браузер, одноразовый секрет, отсутствие сохранения в storage, поиск, страницы, отзыв, мобильная вёрстка и очистка при выходе. Скрипт создаёт тестовые пароли; запускать только на одноразовом стенде.

Ручная проверка замены пароля в Monal/Conversations и повторной регистрации push после перехода выполняется отдельно. Существующие рабочие устройства автоматически не переводятся и не отзываются.
