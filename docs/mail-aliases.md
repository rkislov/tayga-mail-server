# Алиасы доменов и почтовых ящиков

Алиас домена связывает дополнительное DNS-имя с основным доменом. Если
`example.org` — алиас `example.com`, почта на `ivan@example.org` поступает в
`ivan@example.com`. Это также действует для персональных алиасов и групп:
`sales@example.org` использует тот же адрес `sales`, что и основной домен.
Новые ящики и группы автоматически становятся доступны через алиасы домена.
Неизвестный или отключённый получатель не становится catch-all и отклоняется.

Алиас ящика — дополнительный адрес, который ссылается непосредственно на
учётную запись. Например, `sales@example.com` → `ivan@example.com`.
Можно использовать адрес другого основного домена той же организации.
Владельцем писем остаётся исходная учётная запись: отдельные пароль, квота,
папки и календарь не создаются. Вход выполняется по основному адресу. При отправке можно выбирать основной
адрес, алиас ящика и соответствующие адреса на алиасах домена.
Алиасы ресурсов бронирования не создаются.

## Интерфейс администратора

В списке доменов организации нажмите **Алиасы**. В списке пользователей
выберите действие **Алиасы ящика** в строке пользователя. В обоих окнах
доступны список, добавление, изменение адреса и удаление. При добавлении
алиаса ящика выбирается основной домен адреса.

Изменение алиасов домена доступно глобальному администратору, как и создание
основных доменов: имя занимает общий для всех организаций DNS-пространство.
Администратор домена может просматривать доменные алиасы и управлять алиасами
ящиков при наличии прав и на ящик-получатель, и на домен дополнительного адреса.
При чтении скрываются алиасы доменов вне его полномочий.

Для доменного алиаса настройте MX на этот почтовый сервер. Создание записи в
админке само по себе не меняет DNS. Имена международных доменов сохраняются
в ASCII/Punycode. Адреса сравниваются без учёта регистра.

## Отправка от имени алиаса

В окне нового письма поле **От** содержит основной адрес и все действующие
адреса этого ящика. При ответе на письмо, пришедшее на алиас в To/Cc,
он выбирается автоматически. «Ответить всем» исключает собственные алиасы
из получателей. Копия отправленного письма хранится в «Отправленных» основной
учётной записи; пароль и квоты также остаются у неё.

`GET /api/v1/mail/senders` возвращает `{"addresses":[...],"default":"..."}`
для текущего пользователя. В `POST /api/v1/mail/send` укажите поле
`"from":"sales@example.org"`; без `from` используется основной адрес.
Адрес передаётся и в MIME From, и в SMTP envelope. Чужой или удалённый алиас
возвращает `403`, некорректный адрес — `400`.

SMTP submission и FlowSync также разрешают From с собственным алиасом.
SMTP проверяет права и на MAIL FROM, и на From заголовка, повторно после DATA.
Несколько заголовков From отклоняются. Удаление алиаса отзывает возможность
следующей отправки. Явно выданное ящику право делегирования `can_send_as`
учитывается серверной проверкой отправителя; право чтения само по себе
не разрешает отправку.

Для домена-алиаса настройте SPF и DKIM отдельно. Он отображается в списке
доменов инструмента DKIM; подпись использует домен видимого From.
Очередь подписывает и письма из веб-почты. Ключ основного домена автоматически
не используется для другого домена. При переименовании или удалении доменного
алиаса его прежняя управляемая привязка DKIM удаляется.

## API

Все запросы требуют административного Bearer-токена. Идентификаторы в путях
относятся к основным доменам и учётным записям.

- `GET /api/v1/admin/domains/{domain_id}/aliases` — список в поле `aliases`.
- `POST /api/v1/admin/domains/{domain_id}/aliases` — создание с JSON
  `{"name":"example.org"}`.
- `PATCH` или `PUT /api/v1/admin/domains/{domain_id}/aliases/{alias_id}` —
  переименование с таким же JSON.
- `DELETE /api/v1/admin/domains/{domain_id}/aliases/{alias_id}` — удаление.
- `GET /api/v1/admin/users/{user_id}/aliases` — список в поле `aliases`.
- `POST /api/v1/admin/users/{user_id}/aliases` — создание с JSON
  `{"local_part":"sales","domain_id":"основной-домен-ID"}`. Если `domain_id`
  отсутствует, используется основной домен ящика.
- `PATCH` или `PUT /api/v1/admin/users/{user_id}/aliases/{alias_id}` — изменение
  с JSON `{"local_part":"support"}`. Получатель и домен существующего алиаса
  не меняются; для переноса удалите запись и создайте новую.
- `DELETE /api/v1/admin/users/{user_id}/aliases/{alias_id}` — удаление.

Создание возвращает `201` и запись алиаса, изменение — `200` и запись,
удаление — `200`. Ошибки: `400` — некорректный адрес или цель,
`401` — нет авторизации, `403` — недостаточно прав, `404` — запись или цель
не найдена, `409` — адрес уже занят. Алиас ящика возвращает `id`, `domain_id`,
`user_id`, `local_part`, `email`, `created_at`; доменный — `id`, `domain_id`,
`name`, `created_at`.

## Доставка и обновление

Доставка по SMTP, из веб-почты, FlowSync и локального Sieve redirect использует
общий механизм разрешения адресов. Если в одном письме указаны основной адрес,
его алиас и группа с этим ящиком, локально сохраняется одна копия. Для прямого
адресата исходный SMTP RCPT сохраняется в Sieve envelope. Доменные алиасы
учитываются при определении локального участника календарного приглашения.

Доменный алиас всегда ссылается на основной домен, а персональный — на ящик;
цепочки и циклы не создаются. Имена основных доменов и доменных алиасов
не могут пересекаться. Адрес ящика, алиаса и группы также занимает одно общее
пространство внутри домена. Проверки выполняются в транзакциях, включая
конкурентное создание адресов.

Миграция **054_aliases** добавляет таблицу `domain_aliases` для SQLite и
PostgreSQL. Существующая таблица `aliases`, ящики и сообщения сохраняются.
Удаление алиаса прекращает приём на этот адрес и не удаляет письма.
Удаление учётной записи удаляет её алиасы; удаление основного домена удаляет
его доменные алиасы и дополнительные адреса в нём.

Экспорт резервной копии включает `meta/domain_aliases.json` и
`meta/aliases.json`. Восстановление поддерживает архивы без этих файлов и
повторное восстановление совпадающих алиасов; конфликт не переназначает адрес
другому получателю.
