## Проверка резервной копии и миграции

До установки создан новый зашифрованный согласованный снимок остановленной Tayga:
59 520 файлов, 4 967 144 060 байт исходных данных, 2 672 160 894 байта архива.
Расшифровка и полное чтение tar, SHA-256 каждого файла, SQLite integrity_check,
счётчики и хеш прежнего бинарника проверены. Снимок исключает старые бэкапы,
журналы и отдельную установку/сборку/исходники Rspamd. Архив, ключ и частный
отчёт хранятся на компьютере администратора вне репозитория.

На извлечённой копии **реальной** БД выполнено открытие новым кодом и миграция
065: получено ноль FK-нарушений, 169 архивных строк побайтно по значениям JSON
сопоставлены с исходными строками, счётчики сообщений, пользователей, календарей,
приглашений и задач сохранены. После этого тот же результат сверён на сервере.
Проверка текущих файловых ссылок перед обновлением не нашла отсутствующей почты.
Приёмка восстановления целой установки на чистом узле остаётся отдельной работой.

Прежний бинарник и конфигурация сохранены в
`/var/lib/tayga/backups/pre-0.10.1-20261105-212257/`. Архив метаданных миграции
065 намеренно остаётся при откате; возврат бинарника не восстанавливает БД
из старого снимка и не должен терять почту, поступившую после копирования.

## Клиентские результаты

В рабочем Thunderbird восстановлена и повторно получена иерархия с новым
сервером: siem видна, письма загружены, новые поступают, курсор иерархии получен.
Число писем продолжает меняться из-за новых поступлений.

В журнале подтверждён прежний отказ больших MoveItem: 1808/1806 элементов
получали ErrorBatchProcessingStopped, а три элемента — NoError. Исправленный
путь проверен на 1808 сообщениях с сохранением файлов, флагов и выдачей
индивидуальных результатов. Повторное удаление всей рабочей папки агентом
не выполнялось; приёмка пользовательской операции фиксируется отдельно.

В основном календаре iPhone обнаружен повтор ответа с тремя неправильными
Calendar:Until. Даты исправлены в сохранённом ответе с резервированием старого
состояния, сохранением SyncKey и самих событий. Новый код исправляет также
генерацию дат повторений/исключений и повтор сохранённых ответов. Тест доказывает,
что принятый Add при таком ремонте не выполняется повторно. Получение конкретного
импортированного из письма события сервером после обновления пока требует
подтверждения с телефона; наличие карточки на iPhone не заменяет эту проверку.

Общий Go-прогон, целевые race-тесты, нативный Thunderbird во временном профиле,
GitHub CI, CodeQL и Release workflow прошли. Thunderbird XPI остаётся 2.4.0.
