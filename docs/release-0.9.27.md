# Tayga Mail 0.9.27

Оргструктура домена получает выбор источника: ручное управление администратором или вложенные группы LDAP/Active Directory. Выпуск также исправляет чтение и поиск писем в старых кириллических кодировках при миграции через IMAP.

## Оргструктура из LDAP/AD

- **Тенанты → домен → Оргструктура и группы рассылки → Источник**: ручной режим либо LDAP/AD при включённой доменной авторизации.
- Отдельная ветка групп, фильтр, атрибуты названия/адреса/состава, предварительный просмотр и обновление по расписанию. Системный администратор ограничивает доступную ветку параметром `organization_base_dn`.
- Вложенные группы образуют отделы; участники связываются по email с существующими ящиками этого домена. Импорт не создаёт пользователей и не меняет роли.
- Стабильные ID при переименовании объектов с `objectGUID`/`entryUUID`, сохранение ручных групп, проверка конфликтов адресов и версий, циклов и нескольких родителей.
- Полный снимок применяется одной транзакцией. Ошибка подключения, неполный/пустой ответ или нарушение ограничений сохраняют прежнее дерево.
- Постраничный поиск и чтение диапазонов состава больших групп Active Directory. Окно источника адаптировано для мобильного экрана.

Подробная настройка и границы импорта: [оргструктура](organization-directory.md). Модель использует группы; построение дерева из OU и Outlook Hierarchical Address Book остаются отдельными этапами. Рабочий LDAP не включается автоматически при обновлении.

## Кириллические письма и IMAP

- Единое декодирование KOI8-R, Windows-1251, `win-1251`, `win1251` и `cp1251` в заголовках и текстовых MIME-частях.
- Корректное извлечение текста из вложенных `multipart/mixed`/`multipart/alternative`, Base64, quoted-printable и 8bit для индекса и отображения.
- IMAP ENVELOPE сохраняет адреса с именами в старых кодировках; SEARCH и UID SEARCH корректно обрабатывают кириллические литералы после преобразования в UTF-8.
- IMAP APPEND и миграция сохраняют исходные байты, вложения, флаги и дату. Ошибка неизвестной кодировки не скрывает доступные заголовки от IMAP-поиска.

Новый импорт индексируется с исправленным декодированием. Индекс ранее сохранённых писем автоматически не перестраивается. Неизвестные или неверно объявленные кодировки не гарантируют правильного отображения: [миграция](migration.md).

## Обновление и проверка

Миграция **053_directory_source** добавляет приватный внешний ID группы и индекс в SQLite/PostgreSQL. Существующие группы остаются ручными, их состав и адреса сохраняются. Письма, учётные записи и календарные объекты не преобразуются.

Проверены:

- полный набор `go test ./...`, сборка веб-интерфейса;
- LDAP Bind/Search по TCP на тестовом каталоге, предварительный просмотр/применение и сохранность дерева при ошибке;
- пагинация LDAP, диапазоны AD, ограничения домена и ветки, права HTTP API;
- импорт, смена режима, стабильные ID и конкурентные изменения на SQLite/PostgreSQL 16; профильные тесты с детектором гонок;
- реальный IMAP APPEND/FETCH/SEARCH/UID SEARCH с четырьмя кириллическими кодировками, повторная миграция без дублей и MIME-декодирование в вебе/FlowSync;
- настройки источника при ширинах 390 и 1440 px, сохранение режима и обработка отказа подключения.

Подключение к конкретному рабочему AD требует настройки доступных веток, атрибутов и сервисной учётной записи. Автотесты протокола не заменяют эту приёмку.
