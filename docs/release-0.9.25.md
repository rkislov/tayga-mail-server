# Tayga Mail Server 0.9.25

Встречи, созданные или изменённые организатором через CalDAV, теперь используют общую очередь приглашений. Раньше этот путь сохранял событие, обходя рассылку и обновление обычных личных копий участников.

- Создание, изменение и отмена через PUT/DELETE атомарно сохраняют событие, бронирования помещений, копии участников и задания REQUEST/CANCEL.
- Повторное сохранение, изменение личного напоминания и служебных полей не отправляют приглашения заново. Значимая правка повышает версию, даже если клиент этого не сделал.
- Учитывается SCHEDULE-AGENT: адреса, для которых приглашения отправляет сам клиент, не получают вторую серверную рассылку.
- Устаревшие PUT/DELETE отклоняются по ETag. Удаление или правка полученной копии не отменяет встречу организатора и не меняет его бронирования.
- Личные напоминания и категории организатора исключены из календарных писем; правила повторений, исключения и часовые пояса сохраняются.

Новых миграций БД нет. Старые события массово не пересылаются; рассылка относится к новым изменениям организатора через CalDAV. Сервер не объявляет полную поддержку RFC 6638: ответы участника через CalDAV, scheduling discovery/inbox/outbox и Schedule-Tag остаются в дорожной карте. Для ответа доступен веб-интерфейс. EWS/ActiveSync будут подключены отдельным этапом.

Проверки: HTTP-сценарий CalDAV, повтор и конфликт версии, локальные копии и ресурсы, CLIENT/NONE, откат при ошибке записи; общие Go-тесты, race-проверки календаря/storage/DAV/API/FlowSync, отдельный PostgreSQL 16. Проверка конкретных мобильных приложений остаётся отдельной приёмкой.

Подробнее: [календарь и рассылка](https://github.com/rkislov/tayga-mail-server/blob/v0.9.25/docs/calendar-scheduling.md).
