# Целостность ссылок на письма

В 0.10.1 исправлено включение SQLite foreign_keys и busy_timeout только на первом соединении. Настройки теперь задаются через connection hook при каждом открытии физического соединения. Регрессионный тест принудительно заменяет соединение, удаляет письмо и проверяет каскадное удаление метаданных и запрет новых нарушенных ссылок.

Миграция 065 проверяет только отсутствие messages.id у travel_jobs и ews_mail_metadata. Она сохраняет полную исходную строку в JSON в storage_orphaned_message_metadata, затем удаляет рабочую строку. Исходные message_id и source_table остаются ключом архива; архив не имеет ссылки на отсутствующее письмо. Ошибка архивирования или удаления откатывает всю транзакцию. Корректные строки и сообщения не меняются. Другие виды нарушений эта миграция не скрывает и не исправляет.

Во время диагностики mail.kislovs.ru до обновления найдены 168 завершённых travel_jobs и одна ews_mail_metadata без письма. Проверка текущих ссылок messages.file_path не обнаружила отсутствующих файлов; прежняя запись о недостающем источнике на момент этой проверки не воспроизвелась. Это проверка наличия файлов, а не полная приёмка восстановления.

Для проверки после обновления:

```sql
PRAGMA quick_check;
PRAGMA foreign_key_check;
SELECT source_table, count(*) FROM storage_orphaned_message_metadata GROUP BY source_table;
```

Архив содержит частные метаданные; экспортировать его следует с ограниченными правами и хранить вместе с резервной копией. При необходимости вернуть рабочие строки сначала восстановить соответствующие родительские письма, затем проверить владельца и применить поля row_data. Автоматический откат не возвращает нарушенные ссылки и не удаляет архив. Схема PostgreSQL поставляется отдельно; её приёмка и восстановление на чистом узле остаются в дорожной карте.
