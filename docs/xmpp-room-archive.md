# История групповых чатов

Локальные комнаты `room@web-groups.DOMAIN` сохраняют историю для текущих участников. Нативные XMPP-клиенты получают её через [XEP-0313](https://xmpp.org/extensions/xep-0313.html) (`urn:xmpp:mam:2`) на адресе комнаты; веб-чат показывает последние 80 сообщений и кнопку **«Загрузить предыдущие сообщения»**. Веб и XMPP используют один архив и одинаковые идентификаторы сообщений.

## Доступ

- Читать архив может текущий участник, администратор или владелец комнаты, даже если он сейчас не вошёл в неё через MUC.
- Новый или повторно добавленный участник получает доступ ко всей сохранённой истории комнаты. Это сохранённая политика существующих групп; отдельного ограничения «только с момента вступления» нет.
- Исключение прекращает выдачу новых страниц и отправку новых сообщений всем ресурсам участника. Восстановление SM-потока повторно проверяет членство перед входом в комнату. Уже полученные копии сообщений на чужом устройстве сервер удалить не может.
- Проверяется действующий аккаунт и совпадение его текущего тенанта с тенантом владельца комнаты. Отключённый или переведённый в другой тенант пользователь не получает архив, новые сообщения и список прежних комнат.
- Комнаты остаются закрытыми, постоянными и неанонимными по [XEP-0045](https://xmpp.org/extensions/xep-0045.html). Архив содержит ник и реальный JID автора; для старых сообщений и веба доступен bare JID, для новых нативных сообщений — JID с ресурсом.

Проверка членства, изменение состава, выдача MAM и отправка сообщений сериализованы в активном процессе. Поддержка нескольких одновременно активных процессов и распределённого отзыва прав относится к OPS-02.

## Протокол

Комната объявляет `urn:xmpp:mam:2` в `disco#info`. Поддерживаются форма запроса, фильтры `with`, `start`, `end` и RSM `max`, `after`, `before`. Пустой `before` выбирает последние сообщения. На страницу выдаётся до 100 сообщений; `max=0` возвращает количество. Границы дат включаются в выборку. Bare JID в `with` выбирает все ресурсы автора, полный JID — только известный архиву ресурс.

Курсор действует только в своей комнате. Неизвестный или чужой ID даёт `item-not-found`, отсутствие членства — `forbidden`. Неизвестные фильтры и расширения отклоняются, чтобы не расширить запрос. `#extended`, индексный поиск, поиск текста и настройка архивирования через MAM prefs не объявляются.

Ответы идут только запрашивающему ресурсу, без Carbons. Вложенная MUC-строфа имеет namespace `jabber:client`, `from=room/nick`, не содержит `to`; `stanza-id` совпадает с ID живого сообщения и ID результата MAM. Метаданные автора строит сервер. Повторная отправка с тем же `origin-id` не создаёт новую запись.

Веб API: `GET /api/v1/chat/rooms/history?room=JID&limit=80&before=ID`. Параметр `before` можно не передавать для первой страницы. Ответ содержит `messages`, `total`, `complete`, `first`, `last`; сообщения расположены от старых к новым. API использует обычную авторизацию веб-чата, отдаёт `Cache-Control: no-store`, коды 403 при отсутствии доступа и 404 при неверном курсоре. Браузер сохраняет живые SSE-сообщения при получении страницы, исключает дубли по ID и отбрасывает ответы после смены чата или выхода из аккаунта.

## Миграция и откат

Миграция 058 для SQLite/PostgreSQL добавляет последовательность приёма в каждой комнате, счётчик и JID автора. Старые даты UTC приводятся к фиксированной точности, старые сообщения получают порядок по дате и ID. Их ID и содержимое не меняются. Новые сообщения упорядочиваются по приёму даже при одинаковых датах или переводе часов назад.

Счётчик и запись сообщения сохраняются одной транзакцией. При откате **бинарного файла** прежняя версия может писать строки с нулевой последовательностью; после возврата новой версии они получают последовательность и нормализованную дату перед чтением или следующей записью. Одновременно запускать старый и новый активные процессы не следует. SQL Down не нужен для обычного отката бинарного файла.

## Проверки

- `go test ./...` — полный набор тестов.
- `go test -race ./internal/xmpp ./internal/httpapi -run 'Test(Room|ChatRoom|MUC|MAMWire)'` — 257 сообщений, обе стороны пагинации, одинаковые даты и обратный ход часов, фильтры, изоляция курсоров, реальные TCP-сессии двух устройств, восстановление SM, отзыв членства, перенос аккаунта между тенантами, повторная отправка и API.
- `TAYGA_TEST_ROOM_POSTGRES_DSN=postgres://... go test -race ./internal/xmpp -run TestRoomArchivePostgres` — временная схема PostgreSQL, обновление существующих строк, страницы, запись старым бинарным файлом и откат транзакции. DSN должен указывать на отдельный тестовый PostgreSQL.
- `TMS_URL=http://127.0.0.1:PORT node scripts/check-room-archive.mjs` — одноразовый локальный сервер с `admin@example.com / changeme`; скрипт создаёт тестового пользователя, две группы и сообщения. Проверяет реальный API, мобильную вёрстку, 257 сообщений, поздние ответы при переключении чатов, пересечение истории и SSE и выход из аккаунта. Запрещён запуск против рабочего сервера.
