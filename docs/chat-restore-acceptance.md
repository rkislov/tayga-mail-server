# Приёмка чата и восстановления — 19 ноября 2026

## Изолированный автоматический стенд

`TestFullSnapshotRestoresMattermostChatAndSessions` создаёт отдельную SQLite-установку с тестовыми учётными записями, двумя сессиями владельца, участником и чужим тенантом. Через API Mattermost создаются личный и открытый каналы, членство, портретное PNG, сообщение, избранное и регистрация push. Доставка во внешний шлюз не запускается.

После создания зашифрованного age-снимка исходный каталог переименовывается. Восстановление выполняется в новый каталог. Проверены через API и службы TMS:

- сохранение идентификаторов и отсутствие дубликата при повторе отправки;
- история, непрочитанные, отметка чтения, членство и настройки;
- байты оригинала, preview и thumbnail, размеры портретного изображения;
- отказ чужому тенанту в доступе к сообщению и фото;
- сохранение входа, новый вход и завершение другой сессии с сохранением текущей;
- регистрация устройства и сохранённая очередь push;
- сохранность RSA-ключа Jitsi, проверка прежнего JWT, новый JWT участника и отказ постороннему;
- совпадение временных TURN-учётных данных при одинаковом времени запроса.

Снимок и проверка восстановления теперь сверяют записи `chat_files` с файлами на диске и их размерами. Проверяются также старые вложения в BLOB, включая схему до появления `on_disk`. Установки до таблицы `chat_files` поддерживаются. Недостающий, обрезанный или подменённый ссылкой файл, некорректный идентификатор, обрезанный BLOB и внешние пути ключей/плагинов отклоняются.

Пути `vks.signing_key_file`, `vks.turn_secret_file` и `mattermost.plugin_directory` проверяются как часть установки и переносятся при восстановлении в новый каталог. Требования распространяются на итоговую конфигурацию с настройками из БД. Исходный архив не меняется.

## Воспроизведение

```sh
CGO_ENABLED=0 GOTOOLCHAIN=go1.26.10 go test ./...
GOTOOLCHAIN=go1.26.10 go test -race ./internal/chat ./internal/mattermost ./internal/backup/full ./internal/vks
npm --prefix frontend run test:chat
```

Все три проверки пройдены. Go-проверки включают API, сессии, WebSocket, права, push и восстановление. Четыре Node-проверки веб-чата используют DOM и имитацию сети, а не физические клиенты.

## Границы результата

Стенд использует искусственные данные. Его длительность не является RTO рабочего сервера. Реальное видео Jitsi, APNs, сон и смена сети телефона проверяются на устройствах отдельно. PostgreSQL, S3, внешний Jitsi/coturn и другие службы требуют собственной согласованной копии. См. [полный снимок SQLite](backup-full.md).

## Попытка приёмки рабочей копии

На mail.kislovs.ru осталась установленная сборка `0.10.9+mattermost.27.getitem.1.travel.1`; бинарник службы в этой работе не заменялся. Внутри установки найдены 14 внутренних ссылок Rspamd. Для проверки планировалась остановленная копия с материализацией этих ссылок только в отдельном дереве; закрытый ключ age создан отдельно на Mac и на сервер не передавался.

Предварительная оценка объёма без прав администратора была ошибочной — 395 МБ вместо фактических 9,5 ГБ. Остановленная копия заняла свободный диск, после чего TMS не мог открыть SQLite и перезапускался с `disk I/O error (4874)`. Тестовое дерево удалено, свободное место вернулось к 9 ГБ, исходный TMS запущен повторно. Проверены `/readyz` и `/api/v4/system/ping` — HTTP 200, `ActiveState=active`, `SubState=running`, `NRestarts=0`. Дополнительная проверка рабочей SQLite под пользователем службы вернула `quick_check=ok` и ноль нарушений `foreign_key_check`. Рабочие данные и бинарник не заменялись.

Зашифрованный архив рабочей установки не создан, её восстановление не принято. До повтора нужен отдельный том/узел с запасом места. Перед остановкой обязательны успешная проверка объёма от пользователя, читающего все каталоги, `df` и запас для исходной копии, архива и распаковки. Ошибки доступа при `du` запрещено скрывать и трактовать как полный объём. Время копирования 70 секунд не является временем восстановления; после копирования был дополнительный простой из-за заполнения диска.
