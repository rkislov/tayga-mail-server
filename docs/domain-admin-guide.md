# Руководство администратора домена Tayga Mail 1.3.0

Администратор домена обслуживает назначенные ему домены внутри своего тенанта.
Он не получает права администратора всего сервера. Назначение роли и доступных
доменов выполняет уполномоченный администратор; смена параметров страницы или
подстановка чужого ID в API не расширяет права.

## Вход и область управления

Войдите по полному адресу почты и завершите MFA, если она включена. Откройте
«Администрирование → Домены и пользователи». Выберите один из доступных доменов;
если нужного домена нет, попросите администратора сервера проверить назначение.
Не используйте общую учётную запись глобального администратора.

В зависимости от выданных полномочий доступны пользователи, алиасы, квоты и
сервисные настройки этого домена. Серверные слушатели, системные пути, управление
другими тенантами и системные ключи относятся к полномочиям администратора
сервера. Полный обзор существующего меню приведён в
[руководстве администратора](admin-guide.md).

## Пользователи и адреса

1. Проверьте выбранный домен перед созданием ящика или алиаса.
2. Задайте локальную часть адреса, отображаемое имя и разрешённую квоту.
3. Проверьте класс обслуживания и включённые сервисы. Роль администратора не
   следует назначать для обычной работы с почтой или чатами.
4. Перед отключением ящика согласуйте сохранение данных. Отключение учётной
   записи и удаление её содержимого — разные действия.
5. Не публикуйте временные пароли, токены и конфигурации в общих каналах.

## Mattermost, каналы и встречи

«Администрирование → Mattermost» показывает доступные области настроек. Выбирайте
домен, а не весь тенант, если изменение должно действовать только на него.
Проверьте источник наследуемого значения перед переопределением. Настройки
email ↔ чат не включают пересылку сами по себе: нужны выбранные адреса, каналы
и разрешённая политика. Для групповых встреч используйте настроенный Jitsi.

В личном приложении «Чат» можно искать открытые каналы и вступать в них. Для
создания каналов и управления участниками действуют права самого чата. Запросы
к закрытым каналам не открывают их содержимое без членства/права доступа.

Boards и Playbooks включаются отдельно; установку доверенных бинарных модулей,
подготовку PostgreSQL и резервное копирование согласует администратор сервера.
См. [модули и ограничения](mattermost-products.md).

## Агенты и DeepSeek

Экран **«Агенты → Настройки» в 1.3.0 относится к домену текущей учётной записи**.
Выбор другого домена в административном меню не переключает этот экран.
Редактирование доступно, только если у вас есть право управления этим доменом.
Если нужно обслуживать несколько доменов, согласуйте соответствующую учётную
запись/область работы с администратором сервера; не используйте для этого чужую
пользовательскую сессию. Общего наследуемого ключа DeepSeek нет.

### Подключение модели

1. Откройте «Агенты → Настройки → Подключить модель».
2. Выберите DeepSeek. Официальный адрес — `https://api.deepseek.com`, начальная
   модель — `deepseek-flash`; также предлагается `deepseek-v4-pro`.
3. Введите API-ключ своей организации из DeepSeek Platform. Ключ хранится на
   сервере, повторно не возвращается в браузер. Проверьте баланс/лимиты провайдера.
4. При необходимости включите режим рассуждений. Он может увеличить время
   ответа и расход токенов. По умолчанию он выключен.
5. Сохраните подключение. Создайте агента, выберите модель, задайте имя,
   описание и инструкции, включите доступность для пользователей домена.
6. Проверьте ответ в собственном тестовом диалоге без реальных персональных
   данных. Затем сообщите пользователям, какой агент доступен и для каких задач.

Для другого совместимого сервиса выберите «Другой OpenAI-совместимый API».
При смене адреса или типа провайдера прежний ключ автоматически не переносится;
введите ключ для нового подключения. При обычном редактировании пустое поле
оставляет ключ того же подключения. Чтобы полностью убрать ключ, удалите
неиспользуемое подключение. Сначала переключите/удалите связанных агентов.

### Агент и навыки

Имя и описание видны в каталоге. Инструкции агента и подключённых навыков
передаются модели; они не должны содержать пароли или токены. Навык в этой
версии — дополнительная инструкция, а не исполняемый инструмент. Все включённые
агенты доступны пользователям этого домена; отдельных списков доступа к агенту
внутри домена пока нет.

Отключение агента запрещает новые диалоги и новые запросы. Изменение настроек
во время генерации отменяет сохранение её результата: пользователь может
повторить запрос после завершения настройки. Старая форма не перезаписывает
более свежую конфигурацию — при конфликте откройте её заново.

Администратор не получает через этот интерфейс доступ к личным диалогам других
пользователей. Пользователи не наследуют подключения или полномочия владельца
существующего aiagent-бота. Доступ администратора сервера к файлу БД — отдельное
системное полномочие, не функция каталога Agents.

## Диагностика

- **Нет агентов:** проверьте домен текущего адреса, включённость агента и
  доступность Mattermost для области.
- **Нет кнопок настройки:** проверьте назначенную роль и права именно на домен
  текущей учётной записи.
- **Модель не ответила:** проверьте адрес, модель, действительность API-ключа,
  лимиты и исходящий HTTPS с сервера. Не вставляйте ключ в скриншоты/журналы.
- **Ответ уже готовится:** дождитесь текущего запроса. После аварии сервера
  блокировка незавершённого запроса истекает через 150 секунд.
- **Достигнут предел истории:** предложите пользователю удалить ненужный диалог
  или начать новый, если достигнут предел сообщений текущего диалога.
- **Настройки изменены в другом окне:** заново откройте форму и повторите правку.

Для эскалации передайте время ошибки, адрес сервера, домен, вид операции и ID
диалога при наличии. Не отправляйте тексты переписки и API-ключи без отдельной
необходимости. Серверный журнал `agents audit` содержит ID и результат операции.

## Границы версии

Доступен встроенный интерфейс TMS, включая настольный клиент, открывающий его.
Нативное приложение Mattermost для iPhone не получает экран Agents от этого
обновления. Нет MCP/OAuth, исполнения инструментов, входных файлов модели,
потоковой выдачи и синхронизации диалогов с ботом aiagent. Полные технические
ограничения, хранение и защита данных: [Агенты TMS](mattermost-agents.md).


## Подключение Ollama и OpenAI

В «Агенты → Настройки → Подключить модель» доступны отдельные варианты:

- **Ollama:** адрес движка и имя установленной модели из `ollama list`.
  `http://127.0.0.1:11434` относится к серверу TMS. Для другого узла укажите
  частный IP с HTTP либо HTTPS-адрес. Ключ необязателен для локального движка;
  при защите API укажите его отдельно. Сам Ollama и модели эта форма не устанавливает.
- **OpenAI (ChatGPT):** официальный API, ключ из OpenAI Platform и идентификатор
  доступной модели. Форма предлагает варианты, но не проверяет права ключа до
  первого запроса. Браузерный вход в ChatGPT здесь не используется.

После сохранения выберите подключение в настройках агента. Ключи, настройки и
истории по-прежнему разделены по тенанту, домену и пользователю. При переключении
типа подключения новый ключ очищается, прежний секрет другого типа не переносится.
Нативный Ollama использует `/api/chat`; OpenAI — `/v1/chat/completions`.
Подробности и ограничения: [справка Agents](mattermost-agents.md).

### Общие диалоги агентов и инструменты

Агенты доступны также как боты в личных сообщениях Mattermost: `/agents`
показывает каталог домена. Одна ветка DM соответствует одному веб-диалогу;
сообщения и контекст общие. Для продолжения конкретного диалога откройте его
ветку. `/agent-web on|off|status` управляет веб-поиском этого диалога.

Разрешения почты, чатов и веба администратор задаёт отдельно для каждого агента.
Почта и каналы читаются от текущего пользователя. Отправка требует показа
получателя и полного текста, затем кнопки подтверждения или `/agent-confirm ID`.
Подтверждение одноразовое, на 10 минут. SearXNG без ключа или Brave Search
настраиваются в настройках домена. [Подробности и ограничения](mattermost-agents.md#общая-история-с-mattermost-и-инструменты).

Доски создаются в оригинальном интерфейсе Boards: откройте продукт и нажмите
«+» → «Create new board». В Mattermost доступны `/boards` и действие «Доски
Boards» в информации о канале при активном плагине. На iPhone доска открывается
в браузере; при необходимости войдите в TMS. Встроенного нативного редактора
Boards в приложении Mattermost это обновление не добавляет.

### Объём синхронизации и забытые телефоны

В состояниях EWS/EAS общие снимки хранятся без дублирования по пользователю и
коллекции, сжатие/восстановление сохраняет ключи и replay-ответы. Старые записи
можно уплотнить офлайн командой `compact-sync-state -apply -vacuum`; отчёт сверки
не содержит содержимого почты. Срок хранения неактивного EWS-контекста — 180 дней
по умолчанию (`flowsync.state_retention_days`, 0 выключает). Квитанции отправки/
создания задач и действующие EAS-устройства общий TTL не затрагивает.

Для сброшенного телефона используйте «Забыть на сервере», а не удалённую очистку.
Запись скрывается из обычного списка, её ID остаётся заблокированным. Включите
«Показать забытые», чтобы восстановить запись: сначала она возвращается с
блокировкой и новым Provision, затем её можно отдельно разрешить. Старая команда
очистки не возобновляется. [Подробности](storage-migration.md).


## Подключение GPUStack и контроль доступа к моделям

Откройте **Чаты → Агенты → Настройки → Подключить модель**. Для GPUStack
выберите **Другой OpenAI-совместимый API**, заполните название подключения,
базовый HTTPS URL с `/v1`, ID маршрута и ключ GPUStack. Узнайте у системного
администратора базовый URL, разрешённый для кнопки **Проверить подключение**.
Если он уже внесён в список, выберите ID из каталога. Для локального Ollama
используйте отдельный тип **Ollama** и тег установленной модели.

Создайте тестового агента, выберите провайдера и проверьте короткий ответ.
Потом разрешите только нужные инструменты. **Чтение моих календарей** и **Поиск и чтение доступных мне чатов** выполняются с правами автора запроса, включая работу через Mattermost. Календарь доступен только для чтения. Для веб-поиска выберите SearXNG в
**Настройки → Веб-поиск** и проверьте его отдельным запросом со ссылкой.
Проверку начните под обычным пользователем своего домена. Публикуйте
агента только после успешного ответа, проверки инструмента и видимости
в Mattermost. Подробные адреса и команды проверки приведены в
[руководстве по поиску и моделям](install-search-and-models.md).

## Плагины Mattermost и напоминания календаря

В **Администрирование → Mattermost** выберите домен. В **Пакетах
плагинов** можно настроить поля установленного сервером пакета и
включить его для выбранного домена. Сохраняйте токены в настройках
интеграции. Список проверенных возможностей и параметры
Zabbix/Splunk приведены в [руководстве плагинов](mattermost-plugins.md).

В той же области разрешите **Личные напоминания календаря**. Каждый
пользователь отдельно включает доставку через **Чаты → Напоминания**
или `/calendar-reminders on` в Mattermost. Бот отправляет личные
сообщения по собственному календарю пользователя. В общий канал
события не отправляются.
