# Диагностика FlowSync

Passkey (WebAuthn) защищает только вход в веб-интерфейс. Его добавление не должно отключать пароль в ActiveSync/EWS. Если после регистрации ключа клиент начал получать HTTP 401, обновите сервер до сборки с исправлением области действия passkey; удалять ключ и перенастраивать учётную запись не требуется. Отдельная политика `mfa.require_token_for_mfa_users` продолжает требовать OAuth-токен, если у пользователя включён TOTP.

Для временной диагностики ActiveSync, EWS и Autodiscover включите в конфигурации:

```yaml
flowsync:
  enabled: true
  protocol_debug: true
```

После перезапуска Tayga журнал содержит `flowsync request` и `flowsync protocol trace` с общим `request_id`. Тот же идентификатор возвращается в HTTP-заголовке `X-FlowSync-Request-ID`.

Обычная запись содержит протокол, команду, клиента, устройство, HTTP-статус, код ошибки EWS, ссылки на папки, размер ответа и длительность. Диагностическая запись показывает структуру XML или пары WBXML page/token; числовые статусы и типы папок сохраняются. Текст, атрибуты XML, непрозрачные бинарные блоки и прочие значения маскируются. Заголовки авторизации, cookies и полный URL не записываются.

Захват ограничен первыми 64 КиБ каждого направления и 256 элементами структуры. При превышении лимита отмечается `request_truncated` или `response_truncated`. Неполная структура не обязательно означает повреждение протокола: проверьте флаг ограничения. Чтение запроса не меняется — фиксируются только байты, прочитанные обработчиком.

```sh
journalctl -u tayga --since '10 minutes ago' -o cat | grep 'flowsync'
```

После диагностики установите `protocol_debug: false` и перезапустите службу, чтобы прекратить подробные записи. Обычный журнал запросов остаётся включённым. HTTP 200 не означает успешную операцию Exchange: проверяйте `result` и `ResponseCode`.
