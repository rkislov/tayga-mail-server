# OMEMO в групповых чатах

Выпуск 0.9.38 добавляет legacy OMEMO (`eu.siacs.conversations.axolotl`, XEP-0384 0.3) в локальные закрытые комнаты `web-groups.<domain>`. Группа остаётся members-only/non-anonymous: участники знают адреса друг друга. Сервер хранит шифротекст, публичные ключи, состав группы и метаданные, но не закрытые ключи или открытый текст зашифрованного сообщения.

## Как включить

1. Откройте группу и кнопку **Шифрование**. Если браузер ещё не подключён к OMEMO, явно создайте его ключ.
2. Проверьте отпечатки устройств каждого участника и собственных других устройств. В окне участники подписаны ФИО, если оно заполнено, и адресом. Доверие не устанавливается автоматически.
3. Включите шифрование. Настройка действует для отправки из этого браузера; остальные участники включают его в своих клиентах. Группа допускает и обычные сообщения — это не общая обязательная политика шифрования комнаты.
4. Отправьте новое сообщение. Фото и PDF прикрепляются обычной кнопкой: файл шифруется до загрузки, а ссылка с ключом передаётся внутри OMEMO. Лимит веб-вложения — 64 МиБ, срок ссылки — 7 дней.

Каждый другой участник должен иметь хотя бы одно доступное проверенное устройство. Неизвестный/изменившийся активный ключ, отсутствующий набор ключей или отсутствие устройств участника блокируют всю отправку. Автоматического перехода на открытый текст нет. Исключения устройств действуют только в текущем браузере; максимум — 200 устройств на сообщение. Совпадение числовых ID у разных получателей блокирует исходящее сообщение: часть legacy-клиентов выбирает только первый ключ с таким ID. При получении веб-клиент проверяет подходящие ключи изолированно, без изменения сохранённой криптографической сессии после неудачной проверки.

## Состав группы и история

Перед каждой отправкой браузер получает актуальный состав группы и списки устройств. Сервер повторно проверяет версию состава при приёме шифротекста. Если во время подготовки сообщения участника добавили/исключили, сервер возвращает 409 и не записывает сообщение. Обновите устройства и повторите отправку. Удаление с последующим возвращением того же участника тоже меняет версию. Отключённые учётные записи не включаются в список получателей.

Нативные клиенты получают уведомления об изменении affiliation, в том числе для участников не в сети. Они самостоятельно формируют криптографический список получателей. Сервер проверяет членство перед доставкой и выдачей архива; версия состава защищает веб-отправку, но не является проверкой содержимого зашифрованных ключей нативного клиента. Изменение списка устройств не входит в версию состава: браузер получает этот список заново при каждой отправке.

Архив комнаты выдаёт тот же шифротекст через HTTP и MAM с устойчивыми ID и настоящим адресом отправителя. Новое устройство/участник не может расшифровать старые сообщения, если они не были адресованы его ключам. Уже полученные сообщения и файлы нельзя отозвать задним числом. Старый локальный расшифрованный кэш сохраняется после обычного выхода из аккаунта.

Веб-отправитель представлен в XMPP-комнате отдельным участником с зарезервированным ником: presence с настоящим JID приходит до сообщения. Нативный клиент не может занять этот ник. Представление исчезает после закрытия последнего веб-соединения, исключения из группы или удаления комнаты. Короткий HTTP-сеанс без SSE получает временное представление на время отправки.

Шифрованная история предоставляется через **MAM**, а не legacy join history: повторно занятый ник нельзя использовать как доказательство криптографической личности прежнего автора. Если во время отключения пришли новые шифрованные сообщения комнаты, сервер отклоняет SM resume стандартным `item-not-found`. Клиент выполняет новый bind/join и MAM catchup. Это намеренное полное переподключение вместо подтверждения восстановления потока с потерянными сообщениями. Проверка границы архива и повторный вход в комнаты сериализованы с новой доставкой. Если пропущенного шифротекста нет, обычное восстановление SM сохраняется, включая повтор неподтверждённых зашифрованных сообщений.

## Проверки

30 октября 2026 года на отдельных локальных стендах проверены:

- SQLite и PostgreSQL 16: миграция 059, HTTP/native-приём, архив, настоящие авторы, повтор origin-id, запрет отозванного SID, смена состава, отключённый пользователь и отзыв доступа.
- Независимые браузерные хранилища: три участника/четыре устройства; явное доверие, сообщение и ответ, ФИО, перезагрузка и история. Пятое новое устройство блокирует отправку до проверки и не читает прежние сообщения.
- Настоящий HTTPS API: загрузка PNG/PDF через форму, предпросмотр, точные байты скачивания в обе стороны, AES-GCM независимо расшифрован Node.js crypto. Запросы к файловому серверу не содержат ключ, Cookie, Authorization или Referer.
- Изменение состава между подготовкой и POST: 409, отсутствие записи в архиве, исключённый RID отсутствует в следующем сообщении, бывший участник не читает новый шифротекст.
- Реальный TCP/XMPP: смешанный архив из 257 обычных и шифрованных сообщений, страницы/SM, полный bind и MAM после шифрованного сообщения во время отключения. Отдельно проверяется повтор неподтверждённого шифротекста через SM.
- Регрессии личного OMEMO: доверие, исключения, изменение ключей, выход/смена аккаунта, повреждённый шифротекст и сообщения вне очереди. Мобильная форма проверена при ширине 390 px.

Команды: `go test ./...`, `go test -race ./internal/xmpp ./internal/httpapi`, `go vet ./internal/xmpp ./internal/httpapi`; для PostgreSQL — `TAYGA_TEST_ROOM_POSTGRES_DSN=postgres://... go test -race ./internal/xmpp -run TestRoomArchivePostgres`. Используйте только отдельную тестовую БД.

Браузерный сценарий: `TMS_URL=https://localhost:18443 node scripts/check-group-omemo.mjs`. Он изменяет данные и разрешён только на одноразовом локальном сервере с `http.public_url=https://127.0.0.1:18443`, тестовым администратором `admin@example.com` / `changeme` и самоподписанным сертификатом. Сценарий создаёт пользователей, комнаты, устройства, сообщения и файлы. Он не запускает Monal или Conversations.

Ручная приёмка **группового** обмена веб ↔ Monal ↔ Conversations остаётся отдельной проверкой: включить шифрование и проверить отпечатки, обменяться сообщением и PDF, исключить участника, проверить новое сообщение, переключить сеть и проверить историю. Ранее подтверждённая пользователем приёмка личных вложений веб ↔ Monal не заменяет эту проверку. OMEMO 2, федерация S2S и независимый криптографический аудит в данный блок не входят.

## Обновление

Миграция 059 добавляет `web_chat_messages.omemo` и `web_chat_rooms.membership_token`, не меняя старые сообщения и ключи. До установки необходима проверенная резервная копия БД. После обновления перезагрузите страницу без очистки данных браузера.

## Синхронизация групп и заметки себе (31.10.2026)

Локальные группы автоматически добавляются в личные PEP-закладки XEP-0402 (`urn:xmpp:bookmarks:1`, `autojoin=true`) для всех участников, включая создателя. Monal получает их при входе и через уведомления собственным устройствам. Старые членства заполняются однократно при запросе закладок или обнаружении возможностей клиента. Миграция 060 хранит признак этого заполнения; отключение autojoin, пользовательский nick/extensions и удаление закладки не отменяются при следующем входе. Выход/исключение из группы или её удаление убирают соответствующую закладку. Закладки внешних комнат остаются нетронутыми.

Узел приватный (`whitelist`, только владелец), сохраняет несколько комнат. Чужие чтения, подписки и публичный access model запрещены; уведомления не уходят контактам. Проверены SQLite/PostgreSQL, TCP-вход двух устройств и повторное подключение, удаление/повторное членство. После уточнения пользователь подтвердил отображение группы на iPhone: для первого открытия использован список контактов Monal, после чего группа появилась в переписках.

Веб содержит отдельный пункт «Заметки для себя» с собственной историей MAM. Он не дублирует строку статуса аккаунта и не требует подписки на своё присутствие. Пользователь подтвердил появление заметок 31.10.2026.

### Совместимость с Monal 6.4.24

Установленная версия Monal (build 1101) выбирает новый формат только при наличии `pubsub#item-ids`, `pubsub#multi-items` и `urn:xmpp:bookmarks:1#compat-pep`. Без последнего признака она использует старый PEP-узел `storage:bookmarks` и игнорирует уведомления нового формата. Это отличается от текущей ветки develop Monal: проверять совместимость следует по версии установленного клиента ([исходный обработчик](https://github.com/monal-im/Monal/blob/Build_iOS_1101/Monal/Classes/MLIQProcessor.m)).

Сервер поддерживает двустороннее преобразование PEP XEP-0048 ↔ XEP-0402 и объявляет `compat-pep`, а также поддержку значения `max` для числа элементов. Старый список формируется из отдельных новых закладок; замена старого списка атомарно обновляет/удаляет соответствующие новые записи. Удаление закладки не меняет членство в комнате. Неизменившиеся записи не вызывают повторных уведомлений нового формата. Сохраняются nick/autojoin, внешние комнаты, URL-закладки и неизвестные XML-расширения; если старый клиент опустил extensions, сервер сохраняет прежнее значение. Оба представления приватны, уведомления получают только собственные устройства. Существующие старые PEP-закладки импортируются однократно без перезаписи более новых значений. Совместимость с Private XML Storage XEP-0049 (`#compat`) не объявляется.

Диагностика фиксирует формат запроса закладок, число доступных элементов, запросы MUC, успешный вход и причину отказа. Тексты сообщений, пароли комнат и ключи в эти записи не включаются.
