# XMPP через WebSocket

Первый этап XMPP-04 реализован 31.10.2026: XMPP по защищённому WebSocket согласно [RFC 7395](https://www.rfc-editor.org/rfc/rfc7395.html). Код проверен на локальном стенде; в опубликованный выпуск 0.9.39 не входит и на рабочий сервер этим изменением не устанавливался.

## Настройка

Включите XMPP и WebSocket в конфигурации либо в разделе **Администрирование → Сервер → xmpp**, затем перезапустите службу:

```yaml
xmpp:
  enabled: true
  websocket: true
  require_tls: true
  listen: ":5222"
  listen_tls: ":5223"
http:
  tls_listen: ":443"
  public_url: "https://mail.example.com"
```

Адрес клиента: `wss://mail.example.com/xmpp-websocket`, подпротокол — `xmpp`. При другом HTTPS-порту укажите его в URL. Настройка `websocket` по умолчанию выключена. Соединение использует тот же сервер XMPP, что TCP/STARTTLS: личные сообщения, комнаты, PEP/OMEMO, архив MAM, CSI и восстановление потока SM. Работа только через WebSocket допускается с пустыми `listen` и `listen_tls`.

Вход выполняется внутри XMPP через существующие SASL PLAIN/X-OAUTH2. Пароли устройств, строгий режим входа, список активных сессий и отзыв доступа общие с TCP. Cookie веб-сессии, HTTP Authorization и параметры URL не заменяют SASL. Для браузерного клиента страница должна иметь тот же HTTPS origin, что WebSocket. Нативные клиенты могут не передавать Origin. Дополнительный список разрешённых сайтов пока не предусмотрен.

TLS должен доходить до HTTPS-слушателя Tayga. Обратный прокси должен устанавливать HTTPS-соединение с Tayga и сохранять исходный Host; `X-Forwarded-Proto` не делает обычное HTTP-соединение доверенным. Указание адреса WebSocket в клиенте пока ручное: host-meta discovery не добавлено. Встроенный веб-чат продолжает использовать REST/SSE.

## Протокол и ограничения

- Каждый текстовый кадр содержит один полный XML-элемент UTF-8 с самостоятельными пространствами имён. `open`/`close`, перезапуск после SASL и отдельные `features`/`error` поддерживаются. STARTTLS внутри WebSocket не объявляется и не принимается.
- Максимальный входящий элемент — 1 МиБ, глубина XML — 64. DTD, неизвестные префиксы, повторяющиеся атрибуты, несколько элементов в одном кадре, неполный XML, бинарные кадры и whitespace keepalive отклоняются до выполнения обработчиков.
- Не более 256 одновременных WebSocket-соединений на процесс, включая неаутентифицированные. На открытие, вход и привязку ресурса отводится 30 секунд. Выходящая запись ограничена общим тайм-аутом XMPP 10 секунд; лимиты SM остаются общими с TCP.
- Ping/SM и управляющие кадры WebSocket используются вместо пробелов. При потере транспорта SM может восстановить поток после повторного входа теми же учётными данными. Явный XMPP `close` отключает восстановление. Отзыв пароля закрывает соединение и запрещает повторный вход/восстановление.
- Сервер не расшифровывает OMEMO. Полученные рядом с групповым шифротекстом открытые body отбрасываются, как и в TCP. MAM сохраняет исходный шифротекст и идентификаторы.
- Содержимое кадров, пароли и произвольный текст причины закрытия WebSocket в диагностику не записываются.

SASL2, SCRAM с channel binding, защита от downgrade и автоматическое обнаружение адреса остаются следующими этапами. Добавление транспорта не означает завершение XMPP-04 или всей матрицы клиентской совместимости.

## Проверки

- `go test ./...`: общий набор, включая каталог настроек администратора.
- `go test -race ./internal/xmpp ./internal/httpapi -run 'Test(WebSocket|XMPPWebSocket|Resume|RoomMAMTCP|AdminDisconnect|ReplacingResource|XMPPDevicePassword)'`: вход WSS, TCP ↔ WSS, PEP-закладки, MAM, живая групповая доставка OMEMO, отсутствие открытого body, ограничение кадров, неверные состояния, возобновление/повтор, отзыв и остановка сервера.
- `go vet ./internal/xmpp ./internal/httpapi ./internal/config ./internal/settings`.
- `TMS_URL=https://localhost:18443 node scripts/check-xmpp-websocket.mjs`: настоящий WebSocket Chrome, same-origin, обязательный SASL при действующей веб-сессии, bind, ping и повтор неподтверждённого IQ после замены соединения. Только одноразовый локальный HTTPS-стенд с тестовым `admin@example.com / changeme` и `xmpp.websocket: true`; рабочие аккаунты не используются.

Зависимость: Gorilla WebSocket 1.5.3 (BSD-2-Clause); уведомление и текст лицензии включены в распространяемый NOTICE.
