# Оргструктура и группы рассылки

Начиная с 0.9.26, адресный справочник домена содержит дерево подразделений. Каждый узел — группа рассылки со своим адресом; конечные элементы — почтовые ящики сотрудников. Данные хранятся на сервере и общие для пользователей домена.

## Настройка

1. Откройте **Тенанты → строка домена → Оргструктура и группы рассылки**.
2. Нажмите **Добавить подразделение**. Укажите название и часть адреса до `@`: например, `development` для `development@example.com`.
3. Выберите родительское подразделение или корень домена, затем сотрудников. Поиск и страницы списка не сбрасывают уже выбранных участников.
4. При необходимости создайте вложенные отделы тем же способом. Родителя и состав можно менять в редакторе подразделения.
5. В настройках домена включите **GAL**, чтобы сотрудники видели справочник в **Контакты → Оргструктура**, группы в GAL и подсказках адресатов.

Редактирование доступно администраторам в пределах их разрешённых тенантов и доменов. Обычный пользователь видит только свой домен. Отключённые учётные записи не показываются сотрудникам и не получают рассылку; в редакторе администратора они обозначены как отключённые. Ресурсные ящики помещений в состав подразделений не включаются.

## Источник LDAP / Active Directory (0.9.27)

В окне оргструктуры нажмите **Источник**. По умолчанию действует **Вручную администратором домена**. Режим **Группы LDAP / Active Directory** доступен, когда для этого домена включена доменная авторизация LDAP.

Системный администратор задаёт подключение в **Сервер → LDAP → Домены**: URL, TLS/STARTTLS, сервисную учётную запись, базу поиска пользователей и атрибут email. Поле **Доступная ветка оргструктуры** (`organization_base_dn`) ограничивает область чтения групп. Если оно пустое, используется `base_dn`. Например, пользователи могут находиться в `ou=People,dc=example,dc=com`, а группы — в отдельной ветке `ou=Groups,dc=example,dc=com`. После изменения подключения примените настройки с перезапуском службы.

Администратор домена в **Источник** выбирает:

- **Ветка групп (Base DN)** — доступный корень или его дочерняя ветка.
- **Фильтр групп LDAP** — по умолчанию классы `group`, `groupOfNames`, `groupOfUniqueNames`. Дополнительно сервер ограничивает результат адресами текущего почтового домена.
- Атрибуты названия (`cn`), адреса (`mail`) и состава (`member`). Для `groupOfUniqueNames` задайте `uniqueMember` вместо `member`. Значения состава должны быть DN пользователей или вложенных групп.
- Расписание: вручную, каждые 5/15 минут, час, 6 часов или сутки. API допускает интервал от 5 до 1440 минут; `0` отключает расписание. Планировщик проверяет сроки раз в минуту.

Сохраните источник и нажмите **Проверить LDAP**: окно покажет группы, родителей, количество непосредственных участников и предупреждения о ненайденных местных ящиках. Проверка не меняет дерево. **Синхронизировать** заново читает каталог, проверяет актуальный снимок и применяет его целиком. Здесь же показываются время успешного импорта и результат последней попытки.

### Правила импорта

- Подразделения строятся по вложенности групп, а не по OU. У группы один родитель; несколько родителей, цикл или глубина более 32 уровней отклоняют весь импорт.
- Участник связывается по email с существующим ящиком того же домена. Неизвестные адреса пропускаются с предупреждением; новые пользователи и права доступа не создаются. Поиск пользователей ограничен настроенной `base_dn`.
- Вложенные группы должны входить в выбранную ветку и фильтр. Внешние группы или ссылки, которые нельзя полностью прочитать, отклоняют импорт.
- Объекты сопоставляются по `objectGUID`, затем `entryUUID`; если оба отсутствуют — по нормализованному DN. При стабильном идентификаторе переименование группы сохраняет её локальный ID. При сопоставлении только по DN перенос/переименование считается удалением и созданием группы.
- Ручные группы сохраняются. Совпадение адреса с ручной группой, ящиком, алиасом или другой импортированной группой отклоняет импорт; автоматического присвоения ручной группы каталогу нет.
- LDAP-группы, исчезнувшие из успешно прочитанного снимка, удаляются. Если сохранённый ручной отдел ссылается на удаляемого родителя, импорт отклоняется. Почтовые ящики не удаляются.
- В LDAP-режиме ручное редактирование дерева закрыто. Возврат в ручной режим сохраняет текущее дерево и позволяет его редактировать; повторное включение LDAP заменяет ручные изменения ранее импортированных групп.
- Пустой снимок, ошибки соединения/чтения, неполная выдача, referrals, лимиты LDAP и прерванный запрос оставляют прежнее дерево. Для намеренной очистки всех групп переключитесь в ручной режим и удалите их с подтверждением.
- Поддержаны постраничный поиск и диапазоны `member;range=…` Active Directory. Ограничения: до 1000 групп вместе с ручными, 10 000 значений состава группы, 10 000 уникальных DN сотрудников и 100 000 связей за импорт; общий срок чтения — около минуты плюс ограниченное время соединения.
- Конфигурация и импорт используют `revision`: поздний ответ старого запроса не перезапишет новую настройку или более свежий импорт. Пароль подключения, LDAP DN и внешние идентификаторы не выдаются обычным пользователям через справочник.

## Как работает дерево

В левой части окна показаны подразделения и их непосредственные участники. Справа — сотрудники выбранного подразделения, поиск, сортировка по колонкам и страницы по 25 строк. Флажок **Включая вложенные отделы** управляет просмотром состава; на правила доставки он не влияет.

Поиск находит название или адрес подразделения, имя или email сотрудника. Для совпавшего сотрудника раскрывается путь до его отдела. Кнопка **Без подразделения** показывает ящики, которые ещё не входят ни в одну группу.

Нажатие на сотрудника открывает новое письмо с заполненным адресатом. **Написать подразделению** подставляет адрес группы. Само письмо отправляется обычной кнопкой отправки в редакторе.

## Доставка

Письмо на адрес подразделения получают его непосредственные участники и все активные сотрудники вложенных подразделений. Например, если `company@example.com` содержит `development@example.com`, а внутри находится `support@example.com`, рассылка на `company` охватывает все три уровня.

Сотрудник может состоять в нескольких подразделениях. При указании родительской группы, вложенной группы и личного адреса в одном письме он получает одну локальную копию. Разворачивание поддерживают SMTP MX/submission, веб-почта, отправка через FlowSync и локальный Sieve redirect. Старые персональные алиасы сохраняются; группа не становится учётной записью для входа.

Пустая группа или группа без активных получателей отклоняется при приёме адресата: SMTP `550`, веб-отправка `400`. Обычные правила обработки почты и антиспама продолжают действовать. Адрес группы принимает почту по правилам локального домена; отдельных ограничений отправителей или модерации группы в этом выпуске нет.

## Защита структуры

- Адрес группы не может совпадать с ящиком, ресурсным ящиком, алиасом или другой группой домена.
- Родитель и участники принадлежат тому же домену. Нельзя создать цикл или дерево глубже 32 уровней; максимум 1000 подразделений на домен и 10 000 непосредственно выбранных участников на группу.
- Изменение состава и свойств сохраняется одной транзакцией. Версия `revision` предотвращает перезапись более свежих правок другим администратором.
- Удаление требует подтверждения. Сначала нужно перенести или удалить дочерние отделы; почтовые ящики сотрудников сохраняются.
- Домен с оставшимися группами удалить нельзя. Сначала удалите его подразделения и пользователей.

## Совместимость и API

EWS `ResolveNames` возвращает группы как `PublicDL`; `ExpandDL` выдаёт их активных участников без дублей. Это поиск и раскрытие группы в EWS, а не реализация Outlook Hierarchical Address Book. Иерархия отображается в веб-интерфейсе. Импорт вложенных групп LDAP/AD поддержан с 0.9.27; публикация дерева через другие протоколы относится к дальнейшим этапам.

Пользовательское чтение: `GET /api/v1/directory`. Административное чтение/создание: `GET/POST /api/v1/admin/directory?domain_id=…`. Изменение: `PUT /api/v1/admin/directory/{id}?domain_id=…`; удаление: `DELETE` по тому же адресу с параметром `revision`.

В JSON изменения передаются `name`, `local_part`, `parent_id` (пустая строка для корня), `description`, `member_ids` и актуальная `revision`. API сам задаёт домен и идентификатор из проверенного маршрута. Устаревшая версия возвращает `409`. Все запросы требуют авторизации.

Миграция **052_directory_groups** добавляет таблицы групп и состава в SQLite/PostgreSQL. Она не переносит существующие алиасы в группы автоматически и не меняет письма или календарные события.

Настройки источника: `PUT /api/v1/admin/directory/source?domain_id=…` (`mode`, `base_dn`, `filter`, `name_attr`, `email_attr`, `member_attr`, `interval_minutes`, `revision`). Проверка: `POST …/preview?domain_id=…`; применение: `POST …/sync?domain_id=…`. Эти операции разрешены только администраторам соответствующего домена. Миграция **053_directory_source** добавляет приватный внешний ID группы; настройки источника хранятся отдельно для каждого домена.

## Проверки выпуска

Автотесты проверяют вложенную доставку и устранение дублей, сохранение SMTP-алиаса для Sieve, очистку адресатов при RSET/новом MAIL, пустые группы, конфликты адресов и версий, откат ошибочной записи, запрет циклов, конкурентные перемещения и изоляцию доменов. Проверены HTTP API, веб-отправка, EWS поиск/раскрытие, SQLite и отдельный PostgreSQL 16.

В браузере проверены дерево из нескольких уровней с 59 тестовыми ящиками, поиск глубоко вложенного сотрудника, пагинация, создание группы и сохранение участников при смене поиска, ширины 390/1440 px и тёмная тема. Реальные данные организации заполняет администратор.

Для LDAP проверены настоящий обмен Bind/Search по TCP с тестовым каталогом, сопоставление местных ящиков, вложенность, пагинация, диапазоны AD, сохранность дерева при неполном ответе, стабильные ID, конфликты адресов, переключение режимов и конкурентные импорт/настройка. Проверки хранилища выполнены на SQLite и PostgreSQL 16, тесты конкурентности — с детектором гонок. Подключение к конкретному рабочему AD требует настройки его веток, атрибутов и прав чтения.
