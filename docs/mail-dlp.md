# Подключение DLP для почты

С версии 0.9.20 Tayga может передавать исходящую внешнюю почту через SMTP-шлюз DLP. Продукт не привязан к конкретному поставщику: требуется шлюз, который принимает SMTP, применяет свою политику и самостоятельно выполняет дальнейшую доставку.

## Настройка

Откройте **Администратор → Настройки сервера → SMTP и доставка → DLP — исходящая внешняя почта**. Укажите адрес `host:port`, при необходимости логин и пароль, включите очередь и DLP. Обычный `relay.host` должен быть пустым. Сохраните настройки и перезапустите службу Tayga. Пока `enabled` выключен, маршрутизация не меняется.

Эквивалент для bootstrap YAML (рабочие настройки из базы имеют приоритет):

```yaml
smtp:
  queue:
    enabled: true
  relay:
    host: ""
  dlp:
    enabled: true
    host: dlp.example.org:2525
    username: ""
    password: ""
    allow_plaintext: false
```

По умолчанию требуется STARTTLS с действительным сертификатом на имя шлюза. Частный центр сертификации следует установить в системное хранилище доверия. `allow_plaintext` разрешает работу без STARTTLS только для доверенного транспорта; оно не отключает проверку предложенного сертификата. SMTP AUTH PLAIN не передаёт пароль незашифрованным удалённому серверу.

## Доставка и журнал

Маршрут: **Tayga → очередь → DLP-шлюз → сервер получателя**. Если включён DLP, прямая доставка по MX не используется даже при `outbound_direct: true`. Сбой DNS, соединения, TLS или ответ 4xx оставляет письмо в очереди для повторных попыток. Ответ 5xx или исчерпание числа попыток приводит к обычному уведомлению о недоставке. Параметры повторов задаются в `smtp.queue`.

Ответ 250 после DATA означает, что ответственность принял шлюз; это не доказательство доставки конечному адресату и не отдельный вердикт DLP. При асинхронном карантине или отклонении шлюз должен сам уведомлять отправителя. В «Логе писем» сохраняются маршрут DLP, адрес узла, SMTP-ответы, идентификатор очереди и результат попытки. Пароли и содержимое DATA в диалог не записываются.

Настройте дальнейшую доставку на шлюзе: не возвращайте принятую внешнюю почту в Tayga, иначе получится цикл. Проверка конфигурации выявляет очевидный маршрут на собственное имя/loopback и SMTP-порт Tayga, но не может исключить все DNS-алиасы и внешние циклы.

## Границы первого этапа

Проверяются внешние получатели всех отправлений, проходящих через SMTP-очередь Tayga, включая веб-почту, SMTP и FlowSync. Входящая почта и доставка между локальными ящиками остаются прежними. В письме со смешанными получателями локальные адресаты получают письмо независимо от результата DLP для внешних адресатов. Настройка глобальна для сервера; отдельные политики DLP, карантин, ICAP, зеркалирование, контроль файлов/чата и маршруты по доменам этим выпуском не реализованы.

DKIM формируется Tayga до передачи. Если DLP изменяет подписанные поля или тело письма, шлюз должен выполнить окончательную подпись DKIM. До подключения реальной DLP проверены локальные SMTP-стенды: принятие, отказ 550, обязательный TLS и сохранение письма в очереди при отказе шлюза. Совместимость с конкретным продуктом требует проверки после его выбора.
