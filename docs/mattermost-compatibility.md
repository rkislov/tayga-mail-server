# Mattermost-совместимый чат TMS

TMS хранит сообщения и каналы у себя и предоставляет совместимый API v4 с целевой версией контракта **12.0.0** для
проверенных сценариев Mattermost. Для входа используйте HTTPS-адрес TMS,
почтовый адрес и пароль TMS. При включённом TOTP приложение также запрашивает
код. Совместимость охватывает личные сообщения, открытые и закрытые каналы,
поиск пользователей, вложения и обновления через WebSocket.

## Включение

Укажите публичный HTTPS-адрес TMS в `http.public_url`, добавьте следующие
настройки в YAML и перезапустите сервер:

```yaml
mattermost:
  enabled: true
  plugins_enabled: false
```

Доступ настраивается для сервера, тенанта или домена в разделе **Mattermost**
административного интерфейса. Поиск открытых каналов ограничен тенантом.
Закрытые каналы доступны по приглашению. Сервер хранит чаты TMS и историю XMPP
отдельно. Для существующей истории XMPP используйте совместимый XMPP-клиент.

Официальный клиент Mattermost на iPhone показывает личные сообщения и каналы.
Синхронизация идёт через тот же API, что и в веб-чате TMS. Пользователь может
завершать свои сессии Mattermost в профиле TMS.

## Фото и другие вложения

Лимит загрузки составляет 1 ГиБ на запрос и пять файлов на сообщение. Сервер
проверяет членство в канале при скачивании и просмотре. Полноэкранная галерея
получает размеры JPEG с учётом EXIF. При первом запуске этой версии сервер
обновляет размеры ранее загруженных изображений в файлах и истории сообщений.
Если iPhone сохранил старые размеры, откройте **Информация о канале → Сбросить
кэшированные сообщения**.

Вложения на диске находятся в закрытом каталоге `.mattermost-attachments` рядом
с SQLite-базой или внутри корневого каталога почтового хранилища при PostgreSQL.
Включите этот каталог вместе с базой в резервную копию.

## Звонки и интеграции

Для группового звонка настройте [интеграцию с Jitsi](vks.md). Команда `/meet`
и действие «Начать звонок Jitsi» в меню канала Mattermost на iPhone публикуют
приглашение в канале и открывают встречу в браузере.

Push требует отдельно настроенного шлюза. TMS передаёт служебное уведомление
без текста сообщения. Возможности Mattermost API и хоста плагинов реализованы
частично. Совместимость конкретного плагина проверяется отдельно.

Проверенные версии и границы Plugin SDK, GitHub/GitLab/BBB, Redmine/Jenkins и Zabbix — в [приёмке плагинов API 12](mattermost-plugins.md). Номер контракта не означает полную реализацию сервера Mattermost 12.

Внешние боты с отдельными токенами REST/WebSocket и управлением в веб-интерфейсе — [подключение и ограничения](mattermost-bots.md).

## Межсерверные каналы

Экспериментальные нативные связи TMS ↔ TMS и двусторонний REST-мост вынесены в [отдельное руководство](mattermost-federation.md). Нативная совместимость с оригинальным Connected Workspaces ещё требует лицензированного стенда; наличие API не означает полной совместимости.

### Имя владельца сценария в мобильном Mattermost

В upstream Mattermost Mobile (проверено на commit
`0bbcd9d5cbe0046a77a980498337a2e57902876c`) список сценариев задаёт
`teammateNameDisplay='username'` непосредственно в `PlaybookCard`. Поэтому
он показывает логин даже при полном имени в карточке и серверной настройке.
Изменение логина на ФИО на сервере нарушило бы поиск и упоминания.

Для собственной сборки мобильного клиента подготовлен патч
[`mobile-playbooks-owner-name.patch`](../scripts/mattermost/mobile-playbooks-owner-name.patch):
он переключает список на `full_name` с штатным fallback на логин и обновляет
соответствующие ожидания тестов. Применить из checkout Mattermost Mobile:

```sh
git apply --check /path/to/tayga/scripts/mattermost/mobile-playbooks-owner-name.patch
git apply /path/to/tayga/scripts/mattermost/mobile-playbooks-owner-name.patch
```

Затем нужны тесты и подписанная сборка самого мобильного приложения.
Обновление только Tayga Server не изменяет этот жёстко заданный параметр
в установленном клиенте App Store. Серверные PNG-аватары с инициалами
работают и в стандартном клиенте без его модификации.
