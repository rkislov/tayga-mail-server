# Заметки: сохранность при синхронизации

Первый этап: история документов и защита от потери содержимого при обмене через FlowSync. Расширение мобильного редактора и передача рисунков изображениями — следующие этапы.

## Реализовано

- Перед каждым обновлением заметки база сохраняет предыдущий документ, заголовок и метаданные. Запись новой версии, снимка предыдущей и изменение ctag папок выполняются одной транзакцией. При ошибке истории откатывается и изменение заметки.
- Обновление проверяет исходный ETag непосредственно в SQL. Две записи одной версии не могут молча затереть друг друга. Веб-API возвращает HTTP 409, EWS — ErrorIrresolvableConflict.
- ActiveSync сравнивает текущую заметку со снимком, отправленным этому устройству. Если заметка изменилась или устройство её ещё не получило, Change/Delete возвращает статус 7 и актуальная версия попадает в обычную дельту. Политика для заметок — серверная версия имеет приоритет; выбор клиентской политики конфликтов пока не реализован. Успешный Add не дублируется вторым серверным Add. Повтор последнего запроса возвращает сохранённый ответ.
- ActiveSync различает отсутствие Body/Subject и явно пустое значение. EWS поддерживает SetItemField, DeleteItemField для тела/заголовка и AppendToItemField для тела. Текст с символами HTML при BodyType=Text / Type=1 сохраняется как текст. Усечённое тело ActiveSync отклоняется при записи. HTML с изображениями, таблицами и другими неподдерживаемыми медиа отклоняется, чтобы не сохранять его с потерями.
- EWS возвращает действительный ChangeKey заметки при создании, чтении и изменении. Для правки нужен актуальный ChangeKey; AlwaysOverwrite явно разрешает запись поверх устаревшей клиентской версии, но не отменяет проверку сохранности структуры и атомарную проверку конкурентной записи.
- Клиентская замена непустым телом, в котором стало меньше элементов чек-листа или изменились ссылки на рисунки, отклоняется: ActiveSync 6 / EWS ErrorInvalidPropertySet. Редактирование таких заметок возможно в Tayga. Пустое тело считается явной очисткой и допускается; прежний документ остаётся в истории.
- Change/Delete ActiveSync проверяет принадлежность заметки указанной коллекции и права записи.
- В редактор добавлена «История версий»: до 100 последних версий, текстовый просмотр и восстановление содержимого. Восстановление само создаёт новую запись истории; папка, цвет, закрепление и права доступа остаются текущими.

## API

- `GET /api/v1/notes/{id}/versions` — до 100 последних снимков: id, saved_at, title, body_text; нужны текущие права чтения заметки.
- `POST /api/v1/notes/{id}/versions/{version_id}/restore` с `{"etag":"<текущий etag>"}` — восстановить документ и заголовок; нужны текущие права записи. HTTP 409 при устаревшем etag. Можно восстановить снимок по известному id и за пределами последних 100.

Миграция 055 добавляет note_versions для SQLite и PostgreSQL. Существующие заметки не меняются; первый снимок появляется при следующем обновлении. Снимки автоматически не удаляются по возрасту. Удаление заметки или папки удаляет и историю; это история правок, а не корзина. Файлы вложений не версионируются: явное удаление файла не отменяется восстановлением документа.

## Границы совместимости

Apple ограничивает функции Notes в сторонних аккаунтах. Наличие поддержки Notes/Exchange не означает доступность всех функций iCloud. В этом этапе рисунки ещё не передаются как совместимые изображения, работа без сети не добавлена. Защита структуры намеренно отклоняет также удаление отдельного пункта чек-листа или рисунка через протокол: такое изменение следует делать в Tayga, где доступен исходный документ.

Сохранение изменений объекта и состояния ответа ActiveSync остаётся двумя отдельными операциями: авария между ними — прежнее ограничение replay. Слияние документов и полное разрешение конфликтов Exchange не реализованы.

Источники: [аккаунты Notes на iPhone](https://support.apple.com/guide/iphone/add-or-remove-accounts-iph7262fd4fe/ios), [статусы Sync](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-ascmd/08151746-faf7-40a3-832b-b42e88a0b729), [EWS UpdateItem](https://learn.microsoft.com/en-us/exchange/client-developer/web-service-reference/updateitem).

## Проверка перед выпуском

Автотесты: `go test ./...`, `go test -race ./internal/storage ./internal/flowsync ./internal/httpapi`, сборка frontend. Для одноразового тестового сервера с seed-учётной записью: `TMS_URL=http://127.0.0.1:18089 node scripts/check-notes-editor.mjs` и `node scripts/check-notes-history.mjs` с тем же TMS_URL. Скрипты создают и удаляют тестовые заметки; не запускать на рабочем сервере.

На настоящем iPhone и в Outlook проверить: создание с обеих сторон, изменение и удаление; одновременные правки двух клиентов; очистку тела; правку заголовка богатой заметки; попытку упрощения чек-листа/рисунка; повтор запроса после обрыва связи. Проверить поведение клиента после статусов 6/7 и EWS-конфликта. До этой проверки совместимость конкретных версий клиентов не подтверждена. Миграция PostgreSQL требует отдельного запуска на тестовом PostgreSQL.
